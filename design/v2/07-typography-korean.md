# v2-07 글꼴 전략: 한글 UI 전환, 서브셋, 숫자 전용 큰 글꼴

2026-10-17 · 디자이너 7번 · 대상: 410×502 AMOLED, LVGL 9.5, ESP32-C6(RAM 여유 약 140KB, PSRAM 없음), 플래시 16MB
기준: `design/system.md` 2.4(타이포), `firmware/main/ui.cpp`(현재 Montserrat 14/20/28/40/48), `firmware/partitions.csv`

## 0. 결론 요약

1. UI 는 **한글로 바꾼다.** 영문 고유명(Zoom, Teams, Meet, Chrome, PPT, Excel, HWP, BLE, PC)은 그대로 둔다.
2. 글꼴은 **Pretendard**(SIL OFL, 상업·임베드 가능). 한글과 영숫자가 한 가족이라 섞어 써도 높이가 맞는다.
3. 글자 범위는 **"UI 문구에 실제 쓰는 글자만" + ASCII 95자**(약 275자). KS X 1001 2,350자는 쓰지 않는다(3장).
4. 텍스트 글꼴 4종 + 숫자 2종 + 아이콘 2종, **합계 약 280KB**(앱 4MB 파티션의 7%). Montserrat 는 20 하나만 기호 fallback 으로 남긴다.
5. 최소 글자 크기를 14px → **20px** 로 올린다(한글 획은 14px 에서 뭉개진다).
6. 시계·경과 시간은 **숫자 전용 글꼴 112px / 80px**(글자 12개, 각 약 16KB / 8KB).
7. 굵기는 3단: Medium 500(20px) / SemiBold 600(24px, 숫자) / Bold 700(28·32px). **굵기는 크기별로 파일이 갈리므로 플래시 추가 비용이 없다.**
8. 글꼴은 C 배열로 컴파일해 플래시에 둔다(RAM 사용 0, XIP 읽기).
9. 문구 목록 하나(`shared/strings.ko.json`)에서 글자 집합을 뽑아 펌웨어·시뮬레이터가 같은 글꼴·같은 글자 범위를 쓴다. 범위 밖 글자는 시뮬레이터에서 두부(▯)로 보이게 한다.

## 1. 한글 UI 로 바꿀지

| 항목 | 영문 유지 | 한글 (채택) |
| --- | --- | --- |
| 사용자 | 한국 고교 교사. 회의·발표 중 한눈에 읽어야 함 | 모국어가 인지 시간이 짧다 |
| 현재 문구 | `Show not started`, `hold = blackout`, `PC Bluetooth settings > Add device` 처럼 길다 | 같은 뜻이 절반 길이 ("쇼 시작 전", "길게=암전") |
| 글자 폭 | 영문 20px 평균 약 11px/자 | 한글 20px 약 20px/자(전각). 대신 글자 수가 절반 |
| 비용 | 0 | 글꼴 약 280KB, 문구 검수 |
| 영문 고유명 | | Zoom/Teams/Meet/Chrome/PPT/Excel/HWP 는 영문 그대로(제품명, 사용자가 영문으로 안다) |

규칙
- 라벨은 **2~4자**, 문장형 안내는 **최대 12자**(20px 에서 240px, 410 폭 안). 한 줄 고정, 줄바꿈 금지(연결 대기 안내만 2줄 허용).
- 어미는 쓰지 않는다. 명사형·짧은 동사("연결 대기", "슬라이드쇼 시작").
- 한글 안에 영문 약어가 섞이면 영문은 같은 글꼴의 라틴 글리프를 쓴다(별도 글꼴 없음).
- 설정에 "언어 한국어/English" 토글은 **만들지 않는다**(글꼴 2벌 비용, 사용자는 한국 교사).
- 기기 이름 입력은 ASCII 만 허용한다(BLE 이름 길이 제한). 따라서 사용자 입력 한글 대비 글리프 불필요.

## 3. 서브셋 범위와 크기별 플래시 비용

### 3.1 글자 수 후보

| 안 | 글자 수 | 내용 |
| --- | --- | --- |
| A. 실사용만 (채택) | 한글 약 160 + ASCII 95 + 기호 약 20 = **약 275** | 4장 문구 표에서 뽑은 글자 + 여유 20자 |
| B. 상용 한글 500 | 500 + 115 = 약 615 | 문구를 자주 고칠 때의 안전판 |
| C. KS X 1001 | 2,350 + 115 = 약 2,465 | 어떤 문구든 가능 |

실사용 글자 수는 문구 목록 확정 후 스크립트로 센다(3.3). 현재 문구 기준 한글 고유 음절은 150~170자로 예상한다.

### 3.2 크기별 플래시 비용 표 (4bpp, 압축, 커닝 없음)

추정식: 글리프 1개 ≈ 0.30 × S² + 6 바이트(lv_font_conv 기본 압축, Pretendard 한글 평균). **실측으로 ±30% 보정 필요** — 8장의 2번이 이것이다.

| 크기 | 글리프당 | A 안 (275자) | B 안 (615자) | C 안 (2,465자) |
| --- | --- | --- | --- | --- |
| 20px | 126B | **35KB** | 78KB | 310KB |
| 24px | 179B | **49KB** | 110KB | 441KB |
| 28px | 241B | **66KB** | 148KB | 594KB |
| 32px | 313B | **86KB** | 192KB | 772KB |
| 36px | 395B | 109KB | 243KB | 974KB |
| 40px | 486B | 134KB | 299KB | 1,198KB |
| 20/24/28/32 4종 합계 | | **236KB** | 528KB | 2.1MB |
| 20/24/28/32/40 5종 합계 | | 370KB | 827KB | 3.3MB |

C 안은 채택 4종만 만들어도 약 2.1MB 로 앱 4MB 파티션(현재 1.27MB)에 아슬하게 들어가지만 이득이 없다. 글리프 수가 약 9배인데 교사가 보는 화면은 같다. 또 2,350 세트는 `LV_FONT_FMT_TXT_LARGE`(비트맵 오프셋 1MB 초과) 설정과 빌드 시간이 늘어난다.
bpp 2 로 낮추면 약 45% 감소하나 한글 가는 획이 계단져 20·24px 에서는 쓰지 않는다. 80px 이상 숫자도 글자가 12개뿐이라 4bpp 유지.

### 3.3 서브셋 만드는 법 (단일 원본)

```
shared/strings.ko.json     # 모든 화면 문구 (펌웨어·시뮬레이터 공용)
tools/gen_charset.py       # json + ASCII 0x20-0x7E + 기호 -> fonts/charset.txt, 글자 수 출력
tools/gen_fonts.sh         # lv_font_conv 호출 -> firmware/main/fonts/*.c
tools/check_strings.py     # ui.cpp·sim 소스의 한글 리터럴이 charset 안에 있는지 검사(CI)
```

호출 예(크기·파일만 바꿔 반복):

```
lv_font_conv --font Pretendard-SemiBold.otf --size 24 --bpp 4 --no-kerning \
  -r 0x20-0x7E --symbols "<charset_ko.txt 내용>" \
  --format lvgl --lv-font-name kr_24 -o firmware/main/fonts/kr_24.c
```

- `--no-kerning`: 한글에는 커닝이 거의 없고 테이블 비용만 든다.
- 설정: `CONFIG_LV_USE_FONT_COMPRESSED=y`, `LV_FONT_FMT_TXT_LARGE` 는 A 안에서 불필요, Montserrat 14/28/40/48 비활성.
- fallback 은 생성 후 코드에서 `kr_24.fallback = &lv_font_montserrat_20;`(기호용) 로 연결한다.
- 새 문구를 쓰려면 json 에 추가 → `gen_fonts` 재실행. 글자가 빠지면 `check_strings` 가 빌드를 막는다.

- system.md 의 `title 40px` 은 만들지 않고 `kr_32` 로 합친다(-134KB). `display 112 Bold` 는 `num_112 SemiBold` 로 바꾼다(5.3 번인 근거). 22px·26px 단계도 24·28 로 합친다. 크기 종류가 6개면 비용만 늘고 시각 차이는 작다.

### 5.2 굵기 위계

| 위계 | 굵기 | 크기 | 쓰임 | 색 |
| --- | --- | --- | --- | --- |
| 1 | SemiBold 600 | 112 / 80 | 숫자(시각, 경과 시간) | text-1 `#F2F2F2` |
| 2 | Bold 700 | 32 / 28 | 눌러야 하는 대상의 이름(타일, 버튼, 마이크) | text-1 |
| 3 | SemiBold 600 | 24 | 상태·모드·설정 행 | 모드색 또는 text-1 |
| 4 | Medium 500 | 20 | 보조·힌트·안내 | text-2 / text-3 (`#777` 은 20px Medium 이상에서만) |

규칙: 한 화면에서 굵기·크기 **3단계 이하**만 쓴다. 눌러야 하는 것은 Bold, 읽기만 하는 것은 Medium/SemiBold. 검정 위 밝은 글자는 같은 굵기에서도 번져 굵어 보이므로 **Regular(400)는 쓰지 않는다**(20px 에서 가는 획이 끊긴다).

### 5.3 숫자 전용 큰 글꼴 (80~112px)

글리프: `0123456789` `:` 공백. 12자.

| 항목 | 값 |
| --- | --- |
| 크기 | 112px. 숫자 1개 폭 약 66px, `:` 약 30px |
| 폭 확인 | `12:34` = 4×66 + 30 = 294px(410 안, 좌우 58px 여백) |
| 시계 | `HH:MM`, 24시간제는 `07:30` 처럼 0 채움 |
| 경과 시간 | 99분까지 `MM:SS`(num_112). 100분 이상은 `H:MM:SS` 로 전환하고 num_80 사용: 5×46 + 2×21 = 272px |
| 굵기 | SemiBold 600. 획 두께 약 13px. Bold 는 획 약 17px 로 켜지는 픽셀이 약 30% 많아 번인 위험이 크다 |
| 플래시 | 112px 약 1.4KB/글리프 × 12 = 약 16KB, 80px 약 0.7KB × 12 = 약 8KB |

고정폭 문제: lv_font_conv 는 OpenType `tnum` 을 적용하지 못하므로 숫자 폭이 가변이면 시간이 흔들린다. **자릿수마다 라벨 하나**를 쓰고 폭 66px 슬롯 안에서 가운데 정렬한다. 발표 경과 `12:34`(410 폭 가운데 정렬):

| 요소 | x | w |
| --- | --- | --- |
| 분 십 | 58 | 66 |
| 분 일 | 124 | 66 |
| `:` | 190 | 30 |
| 초 십 | 220 | 66 |
| 초 일 | 286 | 66 |

이득: 초가 바뀔 때 **마지막 자리 라벨 하나**(66×120 ≈ 8K 픽셀)만 다시 그린다. 40줄 부분 그리기 버퍼에 5자리 전체(294×120 ≈ 35K 픽셀)보다 훨씬 싸다. 십의 자리는 10초마다만 갱신. 라벨 5개 × 약 60B = 약 300B RAM. `:` 는 점멸시키지 않는다(번인 + 반복 갱신).

## 6. LVGL 구현 메모

| 항목 | 방법 | 비용 |
| --- | --- | --- |
| 글꼴 선언 | `LV_FONT_DECLARE(kr_24)`, `lv_obj_set_style_text_font(obj, &kr_24, 0)` | 플래시 XIP, RAM 0 |
| 줄높이 | 한글 글꼴 줄높이 = 크기×1.25~1.3(5.1 표). 라벨은 단일 줄 | |
| 라벨 모드 | `LV_LABEL_LONG_CLIP`. 긴 문구가 생기면 짧게 고친다(말줄임 금지) | |
| 숫자 라벨 | `lv_label_set_text_static` + 정적 문자열 배열 `"0".."9"`. `set_text_fmt` 는 쓰지 않는다 | 힙 할당 0 |
| 그리기 비용 | 4bpp 글리프를 플래시에서 읽어 알파 합성. 24px 한글 1글자 약 576px. 화면 한글 약 30자 → 약 20K 픽셀 → 1ms 안팎 | 문제 없음 |
| 번인 | 숫자는 SemiBold. 시계 숫자 색을 `#F2F2F2`→`#CFCFCF`(약 -17%)로 낮출지 시계 디자이너와 협의. 숫자 위치를 1분마다 ±2px 이동 | |
| 빌드 | 폰트 `.c` 는 diff 가 크므로 빌드 단계에서 생성하고 입력(json, otf)만 커밋한다 | |

RAM 영향: C 배열 글꼴은 증가 없음. `lv_binfont_create`(파일 로드)는 쓰지 않는다. 글리프 테이블이 RAM 에 올라오고 파티션 읽기 코드가 필요하다.

플래시 예산: 앱 현재 1.27MB + 글꼴 0.28MB − Montserrat 4종 약 0.12MB ≈ 1.45MB < factory 4MB. `partitions.csv` 는 v0.1.0 이후 고정이므로 **건드리지 않는다**. 음성 제거로 비게 된 `model` 파티션(512KB)에 글꼴을 넣지 않는다(C 배열이 더 단순).

## 7. 시뮬레이터 대응

- `@font-face` Pretendard(Medium/SemiBold/Bold) 를 woff2 로 **서브셋**(`pyftsubset --unicodes-file=fonts/charset.txt`, 약 150KB)해서 쓴다. 펌웨어와 같은 글자만 들어가므로 범위 밖 글자는 두부로 보인다. 문구 누락을 시뮬레이터에서 먼저 발견한다.
- 크기·줄높이·굵기는 5.1 표를 `watch.css` 의 `--wc-fs-*`, `--wc-lh-*` 로 옮기고 `tokens.css` 의 `--wc-type-*` 를 이 표로 갱신한다(22/26/40 삭제).
- 단축키 힌트 mono 글꼴은 만들지 않는다: `Win+1` 은 `kr_20` 라틴 글리프로 충분하다. system.md 의 "mono 대체 허용"을 "mono 폐기"로 확정.
- 숫자는 `tabular-nums` 에 의존하지 않고 5.3 과 같은 고정폭 슬롯 span 을 쓴다.
- `strings.ko.json` 은 펌웨어와 같은 파일을 import 한다.

## 8. 할 일 순서 (구현 담당용)

1. 문구 json 작성(4장) → `gen_charset` 로 실제 글자 수 확인.
2. `lv_font_conv` 로 kr_20/24/28/32 실측 → 3.2 표 추정 대비 오차를 이 문서에 기록.
3. `num_80`, `num_112` 생성 → 5.3 슬롯 라벨 구현, 66px 이 실제 숫자 advance 이상인지 확인(넘으면 슬롯 70px).
4. `ui.cpp` 의 `lv_font_montserrat_*` 를 4장 배정으로 교체, 14px 사용처(`hold = blackout`, `Hi ESP`, 힌트) 제거.
5. 시뮬레이터 woff2 서브셋·CSS 변수 갱신, 두 화면 캡처로 줄 위치 비교.
6. 실기에서 20px Medium `#777777` 힌트 가독성(밝은 방, 야외) 확인. 어두우면 text-2 `#A6A6A6` 로 올린다.

## 9. 열린 질문

- 실측 용량이 추정을 크게 넘으면 `kr_32` 를 `kr_28` 로 합쳐 4종→3종으로 줄인다(B·C 안은 더 크므로 대안이 아니다).
