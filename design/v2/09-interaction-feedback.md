# v2-09 상호작용 피드백 (디자이너 9번)

2026-10-17 · 범위: 탭·길게·스와이프 판정 피드백, 전송 성공/끊김 버림, 에어마우스 중 표시, 손목 튕김 인식 표시, 화면 꺼짐/켜짐, 최소 애니메이션 목록. 진동 모터 없음 → **모든 피드백은 화면뿐**이다. 음성 표시는 없다(기능 제거됨).

기준: `design/system.md` 2.6·5장, `shared/gesture.json`(touch: tapMaxMovePx 12 / holdMs 600 / swipeMinPx 80 / topEdgePx 56, button.longPressMs 2000, airMouse.holdToStartMs 250, flick.cooldownMs 800, power.screenOffMs 20000·brightness 80), `firmware/logic/include/wc/touch_gesture.h`(실행 타일은 **뗄 때** tap, 600ms 유지 = 대안 실행 longPress. 발표 좌/우·회의 칩은 뗄 때 tap).
좌표는 410×502 px, (x, y, w, h). 색 토큰은 system.md 값을 그대로 쓴다. `dim` = 현재 모드 dim 불투명 값. 임계값 원본은 `/shared`, 이 문서의 숫자는 표시용이다.

## 0. 핵심 결정

1. **알파 대신 불투명 색 보간.** 배경이 검정이므로 "검정 위 opacity t"는 `lv_color_mix(dim, 검정, t)` 불투명 색과 같다. 플래시·진행 채움은 `bg_color`만 바꾸고 `bg_opa`는 255 고정 → 알파 합성 비용 0.
2. **scale·transform·그림자·그라데이션·블러 전부 금지.** system.md의 "눌림 scale 0.96", "링 scale .9→1"은 폐기하고 색·테두리 두께·크기(정수 px) 변화로 대체한다(LVGL transform은 레이어 버퍼로 내부 RAM을 수십 KB 먹는다).
3. **애니메이션은 계단(step) 방식.** 값이 바뀔 때만 다시 그린다. 400ms 플래시 = 6번 다시 그림.
4. **동시 애니메이션 최대 2개, 갱신 주기 33ms(≈30fps) 상한**(`LV_DEF_REFR_PERIOD 33`). 프레임당 다시 그리는 면적 예산 ≤ 60,000px(화면의 29%). 가장 큰 것은 발표 좌/우 영역 120×422 = 50,640px.
5. **터치 후 첫 피드백 프레임 ≤ 35ms.** 눌림 색은 애니 없이 즉시 바꾼다. HID 전송은 시각 효과를 기다리지 않는다.
6. **절전·암전 밝기는 패널 밝기 레지스터로**(CO5300 `0x51`), `opacity .5` 합성은 쓰지 않는다(전체 화면 알파 = 가장 비싼 효과). system.md 5.3 "꺼짐 직전 5초 opacity .5" → "밝기 80%→40%".
7. **성공과 버림은 모양이 다르다.** 성공 = 영역이 모드색 dim으로 채워졌다 사라짐. 버림 = 면은 안 채우고 테두리 빨강 + 배너 흔들림 + 글자 "보내지 못함"(색+모양+글자).
8. **꺼진 화면을 깨우는 터치는 삼킨다.** 어두워진(40%) 상태의 터치는 삼키지 않고 즉시 실행한다. 발표 쇼 진행 중에는 아예 꺼지지 않는다.
9. **성능 등급 3단**(6.1): 측정 fps가 낮으면 모드 전환 슬라이드를 컷으로 강등. 눌림·플래시 같은 입력 확인 피드백은 강등하지 않는다.
10. **추가 한글 글리프 약 40자(20·26px) ≈ 플래시 12~14KB.** 새 비트맵 아이콘 없음(LVGL 심볼 `‹ ›`만).

## 1. 터치 판정 단계와 시각 피드백

판정은 `TouchGesture`(펌웨어)·`watch.ts`(시뮬레이터)가 하고, UI는 `press()` 값과 이벤트를 받아 그리기만 한다.

| 시각(터치 후) | 상태 | 화면에서 보이는 것 | 취소되면 |
| --- | --- | --- | --- |
| 0ms (≤35ms 안에 그림) | 누름(down) | **눌림 면**: 대상 면색 → `--wc-accent-dim`, 테두리 2px `--wc-accent`. 애니 없이 한 번에 | — |
| 0~12px 이동 | 탭 후보 | 눌림 유지 | — |
| 12px 초과(`tapMaxMovePx`) | 탭 취소 → 스와이프/당김 후보 | 눌림 면을 **80ms**(2단계)에 원래 색으로 복귀. 이후 1.3 | 복귀 후 다른 피드백 없음 |
| 150~600ms | 길게 누름 진행(대상: 발표 가운데, 실행 타일, 회의 타일) | **채움 진행**(1.2). 150ms 전엔 아무것도 안 해 가벼운 탭이 깜빡이지 않음 | 뗌·12px 이동 시 **160ms**(2단계) 복귀, 전송 없음 |
| 600ms (`holdMs`) | longPress 확정 | 채움 100% + 400ms 플래시 | — |
| 뗌, 길게 아님 | tap 확정 | 눌림 **최소 120ms 유지** 후 dim → 원래 색 **280ms**(합계 400ms, 1.1) | — |

규칙
- 뗄 때 전송하는 대상(실행 타일·발표 좌/우·칩)은 down = 눌림, up = 전송 + 플래시. 40ms 탭이어도 눌림이 **최소 120ms** 보이게 `lv_timer`로 복귀를 늦춘다.
- 누르는 순간 전송하는 대상(에어마우스 클릭, 시트 버튼)은 down에서 전송 + 플래시 시작.
- 같은 대상을 다시 탭하면 진행 중 플래시를 **새로 시작**(큐에 쌓지 않음, 초당 최대 8회).
- 멀티터치는 첫 점만 본다.

### 1.1 성공 플래시 색 계단 (6단계)

면색 = `mix(dim, 면기본색, t)`. 면기본색: 실행 타일 `--wc-surface-1`, 발표 영역 검정.

| 구간 | 0~120 | 120~190 | 190~250 | 250~320 | 320~400 | 400~ |
| --- | --- | --- | --- | --- | --- | --- |
| dim 비율 t | 100% | 80% | 55% | 30% | 12% | 0% |

타일 테두리: 눌림 2px `--wc-accent` → 190ms 시점에 1px `--wc-border`로(정수 두께 교체, 애니 아님).

### 1.2 길게 누름 진행 채움 (150→600ms)

| 대상 | 영역 | 채움 | 확정 순간 |
| --- | --- | --- | --- |
| 발표 가운데 | 120,64,170,422 | 검정 → `--wc-accent-dim` 5단계(150·240·330·420·510ms에 20·40·60·80·100%) | `B` 전송, "암전 중" 칩 즉시 표시(135,330,140,44), 400ms 플래시 |
| 실행 타일 | 타일 183×124 | `surface-1` → dim 같은 5단계. **450ms부터 hint가 "Win+R"(대안 실행 예고)로 바뀌고 `--wc-accent-strong`** | 대안 경로 실행, 테두리 3px `--wc-accent-strong` 120ms 후 1px 복귀 |
| 회의 타일 | 타일 | 같은 5단계 | **키 전송 없음**. 아이콘 on/off 즉시 교체, 라벨이 700ms 동안 "상태 맞춤"(caption) |
| 취소 | — | 현재 색 → 기본색 2단계(160ms) | — |

위젯 1개의 색만 바꾸므로 프레임 면적 = 영역 면적(발표 가운데 71,740px, 타일 22,692px).

### 1.3 가로 스와이프(모드 전환) 판정 표시

"지금 놓으면 전환된다"를 손 떼기 전에 알린다. **화면 내용을 손가락에 붙여 끌지 않는다**(전체 화면 다시 그리기 매 프레임 = 비쌈).

| 이동량 dx | 표시 | 위젯 |
| --- | --- | --- |
| 12px 미만 | 없음 | — |
| 12~79px | 이동 쪽 **반대** 가장자리가 아니라 **끌려오는 쪽** 가장자리에 세로 막대 `6×120`(x 0 또는 404, y 191), 색 `--wc-text-3`. 12px에서 즉시 표시 | 라운드 사각형 1개(radius 3) |
| ≥80px (`swipeMinPx`) | 막대가 **목적지 모드색**(`--wc-accent`)으로 바뀌고 폭 6→12px(x 0 또는 398), 안쪽 중앙 y 239에 목적지 모드 이름 label 22px. 즉시 변경 | 같은 막대 + 라벨 1개 |
| 80px 아래로 되돌림 | 확정 해제(막대 `--wc-text-3`·폭 6) | — |
| 뗌, 확정 / fling(≥0.5px/ms, ≥40px) | 막대·라벨 숨김 → 모드 전환(6.1) | — |
| 뗌, 미확정 | 막대 120ms(`text-3` → `#2B2B2B` → 숨김, 2단계) | — |

"끌려오는 쪽": 오른쪽으로 끌면(이전 모드로) 왼쪽 가장자리, 왼쪽으로 끌면(다음 모드) 오른쪽 가장자리. 막대는 y 191~311이라 모서리 곡률(64px)과 거리가 충분하다.

세로: 실행 모드 쪽 넘기기(세로 스와이프)는 12px 이후 **쪽 점**이 즉시 목적 쪽으로 점프하고 타일은 컷 교체. 위쪽 가장자리(y<56 시작) 아래로 당김 ≥60px(`sheetPullMinPx`)은 시트/설정 진입 애니를 **60px 도달 시점에 시작**한다(놓을 때가 아님) → 확정 느낌.

## 2. 전송 결과 피드백 (성공 / 버림 / 실패)

HID는 단방향이라 "성공" = **BLE 스택이 notify 큐에 넣는 데 성공**했다는 뜻이다. PC가 실제 받았는지는 모른다. 그래서 "전송됨" 같은 글자를 쓰지 않고 면 플래시만 쓴다(과장 방지).

### 2.1 세 결과

| 결과 | 조건 | 눌림 모습 | 확정 모습 | 글자 |
| --- | --- | --- | --- | --- |
| **성공** | 연결됨 && notify OK | 1장 표(dim 면 + accent 테두리) | 1.1 플래시 400ms | 없음 |
| **버림(끊김)** | 눌린 순간 `connected == false` | **눌림 면을 만들지 않음.** 대상 테두리만 2px `--wc-danger`(아이콘·라벨·면 불변) | 테두리 danger **240ms** → 1px `--wc-border`. 배너 흔들림(2.2) | 배너 글자 800ms 동안 **"보내지 못함"** 후 "연결 끊김 · 다시 연결 중" 복귀 |
| **실패**(연결됨인데 notify 오류·큐 가득) | 연결됨 && notify ≠ OK | 눌림 면 보임 → 뗄 때 면 즉시 복귀(애니 없음) | 테두리 2px `--wc-warning` 240ms + 토스트 "전송 실패" | 토스트 |

- 버림은 **큐에 쌓지 않는다**(재연결 후 몰아 보내기 금지, system 5장). 시뮬레이터 HID 로그에는 `--sim-log-dropped` "버림" 행.
- 판정은 터치 down 시점의 캐시된 `connected`로 한다. 빨간 테두리를 보고도 키가 나가는 혼선이 없다. 누르는 도중 연결 상태가 바뀌면 up 시점 값으로 **한 번만** 재판정.
- 측면 버튼 1회(다음)·튕김·에어마우스 클릭·시트 버튼도 같은 3결과. 대상 위젯이 없는 입력(측면 버튼, 튕김)의 버림 = 배너 흔들림만. 배너가 없는 시계 모드는 전송 자체가 없어 반응 없음.

## 3. 에어마우스 중 표시 (발표 모드, 측면 버튼 누른 채)

좌표는 watch-presentation 2.5를 유지하고 **비용만 줄인다.**

| 시각(버튼 후) | 화면 |
| --- | --- |
| 0~249ms | 변화 없음. 이 안에 떼면 "다음" → 오른쪽 영역 성공 플래시 |
| 250ms (`holdToStartMs`) | 시작. 경과 시간·쇼 상태·힌트 **즉시 숨김**(opacity 120ms 폐기). 링 3계단 등장 |
| 250~316ms 등장 | 링 지름 144 → 152 → 160(33ms씩), 중심 (205,260) 유지 정수 px 재배치, 테두리 색 `--wc-accent-dim-border` → 중간 → `--wc-accent` |
| 중에 | 링 `125,180,160,160`(테두리 3px `--wc-accent`, 면 없음), 중앙 점 `199,254,12,12`, 라벨 `0,352,410,28` "포인터"(label `--wc-accent`), 안내 `0,388,410,24` caption `--wc-text-2` "화면 탭 = 클릭". **정지 화면**(IMU 값을 그리지 않음) |
| 화면 탭(클릭) | down: 링 안쪽을 `--wc-accent-dim` 원판(160×160, 불투명)으로 즉시 채움 + 링 4px `--wc-accent-strong`. 120ms 유지 후 4단계(dim 60·30·10·0%)로 280ms 사라짐. scale 없음 |
| 1000ms (움직임 없음) | 링·중앙 점이 `--wc-accent` → `--wc-locked`로 **5계단**(1000~2000ms, 200ms마다 20%). 라벨 "잠금까지…"(caption, `--wc-locked`). 손목이 데드존 밖으로 움직이면 즉시 `--wc-accent`로 복귀 |
| 2000ms | 링 사라짐, 토스트 "제스처 잠김"(`--wc-locked-dim` 면, 자물쇠) 1600ms, 상태줄 자물쇠 표시. 손을 뗄 때까지 아무것도 안 보냄 |
| 버튼 뗌 | 링·점·라벨 **즉시 숨김**, 시간·힌트 즉시 복귀. 커서 이동 정지를 화면 애니가 기다리지 않음 |
| 끊김 중 시작 | 링 테두리 `--wc-disconnected` + 라벨 "연결 끊김", 커서 이동 없음, 탭 = 버림(2.1) |
| 에어마우스 중 스와이프·시트·길게 | 무시(피드백 없음) |

발표 외 모드의 측면 버튼 길게 누름(잠금만): 1000ms에 중앙 `157,205,96,96`에 `--wc-locked` 호(`lv_arc`, 선 8px) 등장 → 5계단 20→100%(1000~2000ms) → 2000ms 토스트. 손 떼면 즉시 사라짐.

## 4. 손목 튕김 인식 표시 (발표 모드)

튕김은 화면을 보지 않고 하는 입력이라 "인식됐는지"가 시선이 스친 순간에 보여야 한다. 탭 플래시와 구분되게 **화살표 글리프**를 더한다.

| 이벤트 | 영역 | 화면 |
| --- | --- | --- |
| 바깥 튕김(`→` 다음), 연결됨 | 오른쪽 `290,64,120,422` | 성공 플래시(1.1) + 영역 중앙 (350,275)에 `›`(LV_SYMBOL_RIGHT, 48px) `--wc-accent` 400ms → 400ms 동안 `--wc-text-disabled`(= 재인식 금지 **800ms** `flick.cooldownMs`) → 숨김 |
| 안쪽 튕김(`←` 이전) | 왼쪽 `0,64,120,422` | 같은 방식, 글리프 `‹` (60,275) |
| 쿨다운 800ms 중 또 튕김 | — | 새 플래시 없음. 회색 글리프가 80ms 동안 `--wc-text-2`로 밝아졌다 복귀("들었지만 무시") |
| 잠금 중 튕김 감지 | 상태줄 자물쇠 `244,14,28,28` | `--wc-locked` → `--wc-text-1` 160ms → 복귀("잠겨서 안 보냄"). 영역 플래시 없음 |
| 끊김 중 | 배너 | 2.2 흔들림 + "보내지 못함" |
| 발표 외 모드 | — | 튕김 기능 꺼짐 → 반응 없음 |

- 탭 = 영역 채움만, 튕김 = 영역 채움 + 큰 화살표. 측면 버튼 1회는 채움만.
- 글리프는 영역마다 `lv_label` 1개(총 2개, 56×56 = 3,136px), 표시/숨김·글자색 변경만. 한글 아님 → 글꼴 추가 0.
- 설정 화면의 "감도 테스트"(설정 담당)는 같은 `‹ ›`를 화면 상단에 띄워 확인하게 한다.

## 5. 화면 꺼짐/켜짐 전환 (`power.screenOffMs` 20000, `brightnessPercent` 80)

### 5.1 단계

| 단계 | 시각(입력 없음) | 밝기·화면 | 입력 |
| --- | --- | --- | --- |
| 활성 | 0 ~ T-5s | 80% | 정상 |
| 어두워짐(예고) | T-5s ~ T | **40%**(레지스터 1회) | **삼키지 않고 정상 실행**, 실행 즉시 80% 복귀(120ms, 3단계) |
| 꺼짐 진행 | T | 40→20→0% 3단계(50ms씩, 150ms) 후 `display off(0x28)`, LVGL 갱신 정지(BLE·IMU만 동작) | — |
| 꺼짐 | T 이후 | 검정 | 5.3 |

T = `screenOffMs`(20초). **발표 쇼 진행 중에는 꺼짐 대신 어두워짐만**: 30초 입력 없으면 40% 유지, 꺼지지 않음(10분 무입력이면 꺼짐). 발표 중 꺼짐은 "다음"을 놓치는 가장 큰 사고 원인이다(전원 담당 합의 필요, 10장).

### 5.2 켜짐 시퀀스 (≈180ms)

1. t=0 깨우는 입력.
2. t=0~20ms: 숨은 상태에서 화면 한 번 렌더(시계 모드는 **시각·배터리 먼저 갱신**해 옛 시각이 비치지 않게). 연결 상태도 이때 확정 → 켜질 때 끊김 배너가 떴다 사라지는 깜빡임 방지.
3. t≈25ms: `display on(0x29)`, 밝기 0%.
4. 밝기 0→20→50→80% **4계단(40ms씩, 160ms)**. 레지스터 쓰기만, 렌더 없음.

### 5.3 깨우기 소스별 규칙

| 깨우는 입력 | 처리 |
| --- | --- |
| **터치 down** | 그 터치 전체(down~up)를 **삼킨다**: 키 전송·눌림 표시 없음. 켜진 뒤 150ms 이내 두 번째 터치도 삼킨다 |
| **측면 버튼 짧게** | 화면만 켠다. "다음" 전송 안 함 |
| **손목 들기**(`wristRaise`, "손목 들면 시계") | 켜고 **시계 모드로**(발표 쇼 진행 중이면 모드 유지) |
| **측면 버튼 길게(잠금)** | 켠 뒤 토스트로 결과 표시 |
| **튕김**(꺼짐 중) | 켜지 않고 무시(오탐 시 화면 번쩍임 방지) |

### 5.4 번인

- 켜져 있는 동안 시계 모드는 **10분마다** 본문+상태줄을 (0,0)→(2,0)→(2,2)→(0,2) 순환 이동(위젯 좌표 일괄 변경 1회 = 전체 다시 그리기 1회). 항상 켜진 AOD는 없다.
- 어두워짐은 글자색을 낮추지 않고 밝기 레지스터만 쓴다(렌더 0).

### 8.2 CPU·메모리

- 메모리: 추가 위젯 약 13개 × 140~200B ≈ **2.5KB** + `lv_anim` 동시 6개(각 ~60B). 레이어·스냅샷 버퍼 없음.
- 알파·레이어 비용 0. 큰 영역(발표 가운데 71.7K)은 radius 0(현재 코드와 같음). 둥근 모서리 면은 가장자리 AA 비용이 있다.
- 전송 경로: `tap → hid_send()`는 UI 밖(BLE 태스크 큐). UI는 결과 이벤트(성공/버림/실패)만 받아 그린다. 큐 길이 4, 가득 차면 "실패".
- 싱글코어에서 IMU(100Hz)+BLE+LVGL이 코어를 나눠 쓴다. 애니 중 IMU 처리가 밀리지 않게 LVGL 태스크 우선순위를 BLE/IMU보다 낮게. 에어마우스 중 화면이 정지라 렌더가 거의 없는 것이 이 설계의 이유다.

### 8.3 펌웨어 팀 측정 요청

1. 발표 좌 플래시 6단계 프레임 시간(평균/최대) — 목표 평균 ≤25ms.
2. 전체 화면 교체 1프레임 시간 — 6.1 등급 기준.
3. 모드 전환 중 IMU 샘플 누락 수.
4. 위 위젯 추가 후 내부 RAM 여유 ≥ 135KB 유지.
5. 터치 down → 첫 프레임 완료 시간(목표 ≤35ms).

### 8.4 새로 필요한 한글 글리프

| 문구 | 글꼴 | 고유 글자 | 플래시 |
| --- | --- | --- | --- |
| "보내지 못함" | 26px | 5 | 1.7KB |
| "전송 실패" | 26px | 4 | 1.4KB |
| "제스처 잠김 / 풀림" | 26px | 7 | 2.4KB |
| "연결됨 / 연결 끊김" | 26px | 5(중복 제거) | 1.7KB |
| "포인터", "화면 탭 = 클릭", "잠금까지…" | 20px | 12 | 2.5KB |
| "상태 맞춤" | 20px | 5 | 1.0KB |
| 합계(중복 제거 약 40자) | | | **≈ 12~14KB** |

계산식: 4bpp 한 글자 ≈ (크기² × 0.5) + 10B → 20px ≈ 210B, 26px ≈ 350B, 32px ≈ 530B. 한글 완성형 2,350자 전체는 26px 기준 약 820KB이므로 문구에 쓰는 글자만 서브셋한다. 다른 디자이너의 화면 문구와 합쳐 한 번에 변환한다.

## 9. 시뮬레이터(sim/) 반영

- 눌림·플래시는 CSS `transition` 없이 JS 시간표(`[0,120,190,250,320,400]`ms)로 같은 6단계 색 계단을 적용한다. 부드러운 transition은 펌웨어와 달라 보이므로 쓰지 않는다.
- 배너 흔들림: `translateX(0,-6,+6,-6,+6,0)` 80ms 간격.
- 화면 꺼짐: 에뮬레이터 안쪽 `.wc-screen`에 `filter: brightness()` 3단계(0.5, 0.25, 0) 50ms 간격. 꺼짐 상태의 첫 터치는 삼키고 HID 로그에 시스템 행 "화면 켬 · 입력 삼킴"을 남긴다.
- 로그 행 제안: `버림 · 끊김`(`--sim-log-dropped`), `삼킴 · 화면 꺼짐`(`--sim-log-system`).
- `prefers-reduced-motion`: A8·A9·A15·A16만 0ms. 눌림·플래시·흔들림은 의미 전달용이라 유지(watch-presentation 5장과 같은 방침).
