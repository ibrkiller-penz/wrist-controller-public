# v2 디자인 03 — 실행 모드 (1쪽 앱 / 2쪽 업무)

2026-10-17 · 디자이너 3번 · 범위: 실행(launch) 모드 1·2쪽의 타일 시각 정체성, Win+N 힌트, 쪽 표시, 길게 누르기 단서, 누름 피드백, 업무포털 비활성.
기준: `design/system.md`, `design/tokens.css`, `docs/research/launcher.md`, `sim/src/core/layout.ts`(타일 좌표 원본), `firmware/main/ui.cpp` buildLaunch. 음성 관련 요소는 넣지 않았다.
좌표는 410×502 화면 왼쪽 위 (0,0) 기준 px. "타일 안 좌표"는 타일 왼쪽 위 기준.

---

## 0. 한 줄 요약

- 1쪽(앱)은 **앱마다 다른 색 + 둥근 사각 이니셜 배지**(라벨 첫 글자), 2쪽(업무)은 **모드색(파랑) + 원형 아이콘 배지**. 모양(사각/원)과 색(알록달록/파랑 한 색)으로 쪽을 구분한다.
- 힌트는 타일 오른쪽 위에 `Win+1` (20px). 길게 누르기(Win+R 대안)가 있는 타일만 오른쪽 아래에 작은 고리(○)가 있고, 누르고 있으면 아래 막대가 450ms 동안 차오른다.
- 쪽 표시는 점 대신 **라벨 탭 `앱 | 업무`**(y 466~495). 눌러서 쪽 전환, 세로 스와이프도 그대로.
- 누름 피드백은 scale 없이(레이어 렌더링 비용) **면색·테두리·배지 반전 3가지**만 바꾼다.

## 2. 1쪽 앱 타일 정체성 (순서는 Win+1~6 작업표시줄 순서)

상표 로고는 쓰지 않는다. 배지는 "라벨 첫 글자"(C, 카, 웹, P, 엑, 한)이고 색은 브랜드 색을 그대로 베끼지 않은 **일반 계열색**이다. 색만으로 구분하지 않도록 글자·위치가 항상 같이 간다(system.md 원칙 4).

| 칸 | 타일 위치 | 라벨 | 배지 글자 | 앱색 (기본 `--wc-app-*`) | dim 면 | 힌트 Win / Mac |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 16,64 | Claude | C | 모래 `#D9A877` | `#271E15` | Win+1 / Spotlight |
| 2 | 211,64 | 카카오톡 | 카 | 노랑 `#F5C518` | `#2C2304` | Win+2 / Spotlight |
| 3 | 16,200 | 크롬 | 웹 | 청록 `#2EC4B6` | `#082321` | Win+3 / Spotlight |
| 4 | 211,200 | 파워포인트 | P | 적주황 `#FF6A3D` | `#2E130B` | Win+4 / Spotlight |
| 5 | 16,336 | 엑셀 | 엑 | 연두 `#8BD450` | `#19260E` | Win+5 / Spotlight |
| 6 | 211,336 | 한글 | 한 | 분홍 `#E86AB8` | `#2A1321` | Win+6 / Spotlight |

- dim은 앱색을 검정 위에 18%로 합성한 **불투명 값**(system.md 2.2와 같은 방식)이라 알파 합성이 없다. 앱색 글자 대비는 dim 면 위에서 약 6~9:1.
- 크롬 배지는 "크"가 아니라 "웹"이다. 이유: 크/카가 한 화면에서 모양이 비슷하고, 사용자가 엣지 등 다른 브라우저를 쓰는 PC에서도 의미가 맞는다. 나머지는 첫 글자. 규칙: **"첫 글자, 단 혼동되면 의미 글자"**.
- 이 6색은 모드색(주황·파랑·초록), 상태색(노랑 경고 `#FFD43B`·빨강·보라)과 가능한 한 겹치지 않게 골랐다. 노랑(카카오톡)은 경고 노랑과 가깝다 — 배터리 경고는 **상태줄**에만 나오고 위치가 달라 허용한다(대신 카카오톡 노랑을 `#F5C518`로 경고색보다 한 단계 붉게 했다).
- 새 토큰(`tokens.css`에 추가할 것): `--wc-app-claude/kakao/chrome/ppt/excel/hwp` 와 각 `-dim`. 모드색 규칙처럼 컴포넌트는 `--wc-app`/`--wc-app-dim` 별칭만 쓰고, 타일마다 인라인으로 지정한다.
- 설정 사이트에서 앱을 바꾸거나 7번째 앱을 넣으면(keymap `icon`/`color` 필드 필요 — 제안) 색이 없는 앱은 중립(`--wc-text-2` 배지 글자 + `--wc-surface-2` 면)으로 그린다. keymap 쪽 필드: `"badge": "C"`, `"hue": "#D9A877"`.

### 2.1 Win+N 힌트

- 오른쪽 위 20px `Win+1`. 의미는 "작업표시줄 N번째 앱". 이 번호가 곧 타일 순서이므로 설치 안내(`settings-install.md`)에 **작업표시줄 고정 순서 1~6 그림**을 넣을 것.
- 폭: 20px Montserrat에서 `Win+Shift+S`가 약 117px라 107px 칸에 안 맞는다 → 힌트 라벨에 `letter_space = -1`을 주고(약 106px), 그래도 넘으면 힌트를 숨기고 타일 `title`(시뮬)·로그에만 남긴다. `Win+L`, `Win+D`, `Win+P`, `Win+1` 등은 넉넉히 맞는다.
- macOS 선택 시 1쪽 힌트는 `Spotlight`(9자, 약 98px)로 바꾼다. 2쪽: 캡처 `Cmd+Shift+5`(letter_space -1에서 약 108px, 넘으면 `Cmd+⇧5` 금지 — 글꼴에 없음 — 숨김), 화면잠금 `Ctrl+Cmd+Q`.
- 매크로 타일 힌트는 keymap의 첫 단계가 아니라 **의미 문구**로 고정: 업무포털 `크롬 주소`(한글 20px × 4 = 80px). 매크로를 그대로 `Win+3 → …`로 줄이면 뜻을 알 수 없다(현재 sim의 `→ …` 방식은 폐기).
- 힌트는 항상 `--wc-text-3`. 눌림 중에는 `--wc-text-2`로 한 단계 밝아진다.

## 3. 2쪽 업무 타일 정체성

앱이 아니므로 앱색을 쓰지 않고 **모드색(파랑) 한 색 + 원형 아이콘 배지**로 "도구"임을 알린다. 배지 면 `--wc-accent-dim`(#0B192E), 아이콘 28×28 `--wc-accent`(#3D8BFF), 색 띠 `--wc-accent`.

| 칸 | 위치 | 라벨 | 아이콘 | 힌트 Win / Mac | 특이사항 |
| --- | --- | --- | --- | --- | --- |
| 1 | 16,64 | 영역 캡처 → 짧게 **캡처** | `i-capture` | Win+Shift+S / Cmd+Shift+5 | |
| 2 | 211,64 | **화면 잠금** | `i-lock` | Win+L / Ctrl+Cmd+Q | 상태줄 잠금(보라, 제스처 잠금)과 혼동 방지: 아이콘은 **파랑**, 라벨에 "화면"을 붙인다 |
| 3 | 16,200 | **바탕화면** | `i-desktop` | Win+D / (없음→비활성) | 토글 |
| 4 | 211,200 | **화면전환** | `i-display` | Win+P / (없음→비활성) | Win+P는 메뉴만 열림. 힌트 옆 보조 문구 없음 |
| 5 | 16,336 | **음소거** | `i-mute` | `MUTE` / `MUTE` | 소비자 키. 현재 소리 상태를 모르므로 켜짐/꺼짐 표시 없음 |

- 라벨은 모두 한글 4자 이하(26px에서 104px) — 여유가 크므로 "영역 캡처"(4자)도 들어가지만, 쪽 1과 길이를 맞추려 **캡처**로 둔다. 선택 사항.
- 새 아이콘(24 그리드, 선 2, `icons.svg`에 추가; 펌웨어는 28px A8로 래스터화):

## 4. 업무포털 비활성 (URL 미설정) — 및 Mac 없는 기능

비활성 조건: ① keymap `url`이 비어 있음(포털) ② 해당 OS 조합이 `null`(Win+P의 Mac). 시스템 표 5장 "비활성" 행을 따르되, **이유를 한 줄 적는 것**이 이 문서의 추가 규칙이다.

| 요소 | 기본 | 비활성 |
| --- | --- | --- |
| 타일 면 | `#141414` | `--wc-bg` `#000000` |
| 테두리 | 1px `#333333` | 1px `#333333` (그대로) |
| 색 띠 | `--wc-accent` | `--wc-border` `#333333` |
| 배지 | 면 `--wc-accent-dim`, 아이콘 `--wc-accent` | 면 없음(투명), **테두리 2px `#4D4D4D`**, 아이콘 `--wc-text-disabled` |
| 라벨 | `--wc-text-1` | `--wc-text-disabled` `#4D4D4D` |
| 힌트 | `Win+…` | **이유 문구** `주소 필요`(업무포털) / `Mac 없음`(Mac 미지원), `--wc-text-3` — 이유만은 읽혀야 하므로 #777 유지 |
| 길게 단서 고리 | 있음 | 없음 |
| 터치 | 키 전송 | 키 전송 없음. 토스트(아래) |

- 이유 문구 폭: `주소 필요` 20px 5자 ≈ 90px, `Mac 없음` ≈ 85px — 힌트 칸 107px에 들어간다.
- 비활성 타일을 눌렀을 때 토스트: x 16, y 396, 378×56, 반경 md(20), 면 `--wc-surface-2`, 글자 20px `--wc-text-1`, 1600ms 유지(`--wc-motion-toast`). 문구: 포털 `주소 미설정 · PC 설정 사이트에서 입력`(약 17자 ≈ 340px, 안 들어가면 `주소 미설정 · 설정 사이트에서`), Mac 없음 `Mac은 이 기능이 없어요`. 토스트가 뜨는 y 396은 타일 E/F(y 336~460) 위로 겹치지만 일시적이라 허용.
- 비활성 타일이어도 **탭 영역은 그대로**(눌러서 이유를 알 수 있게). 길게 누르기는 반응 없음.
- 연결 끊김 상태(5.1절)의 타일과 **시각이 같아 보이지 않도록**: 끊김은 6개 타일 전부 같은 방식으로 죽고 배너가 뜬다. 비활성은 한두 개만 죽고 힌트에 이유가 있다.

## 5. 누름·길게 누르기

### 5.1 발화 시점 (system.md 5의 예외)

| 입력 | 동작 | 이유 |
| --- | --- | --- |
| 탭(손 뗌, 누른 시간 < 450ms, 이동 < 24px) | 기본(Win+N) **손 뗄 때** 전송 | 타일 위에서 세로 스와이프(쪽 전환)·가로 스와이프(모드 전환)가 시작될 수 있어 터치 다운 때 보내면 오발송 |
| 길게(≥ 450ms) | 대안(Win+R 매크로) **450ms 도달 즉시** 전송, 손을 떼도 추가 전송 없음 | 길게 누르기와 탭을 구분해야 하므로 |
| 이동 ≥ 24px | 취소(전송 안 함), 눌림 표시 해제 | 스와이프 인식 |
| 대안 없는 타일(카카오톡, 한글 불확실) | 길게 눌러도 탭과 동일하게 손 뗄 때 기본 한 번만 | 단서가 없는 타일이 반응하지 않으면 혼란 |

- 450ms는 시스템의 중앙 길게 누름(600ms, 암전)보다 짧다. 다른 모드의 값과 섞이지 않도록 `--wc-hold-tile: 450ms`를 `tokens.css`에 추가한다(표시용 사본, 원본은 `/shared`).
- 기본 키는 **지연 없이**(system의 `motion-instant` 정신): 손을 뗀 순간 보낸다.

### 5.2 눌림 시각 (80ms 진입, 160ms 복귀)

| 상태 | 타일 면 | 테두리 | 배지 | 힌트 | 막대 |
| --- | --- | --- | --- | --- | --- |
| 기본 | `#141414` | 1px `#333333` | 면 dim, 글자 앱색 | `#777777` | 숨김 |
| 눌림(0~150ms) | **앱 dim**(2쪽 `--wc-accent-dim`) | 2px **앱색** | **반전**: 면 앱색, 글자 `#000000`(2쪽 아이콘도 `#000000`) | `#A6A6A6` | 숨김 |
| 길게 진행(150~450ms) | 눌림과 같음 | 눌림과 같음 | 눌림과 같음 | 힌트 → `Win+R`(대안 키 이름) | 16→149px로 선형 성장(4px 높이, 앱색) |
| 길게 확정(450ms) | 앱 dim | 2px **`--wc-text-1`** 400ms 1회 점멸 후 복귀 | 반전 유지 | `실행창`(`--wc-accent-strong`) 600ms | 꽉 참 → 160ms 후 숨김 |
| 탭 확정(손 뗌) | 앱 dim → 160ms 후 기본 | 2px 앱색 **400ms 유지** 후 1px 복귀 (`motion-flash`) | 반전 → 160ms 후 복귀 | 복귀 | — |

- scale 0.96은 **쓰지 않는다**. LVGL에서 자식이 있는 객체의 `transform_scale`은 레이어 렌더링(타일 183×124×2B ≈ 45KB 임시 버퍼)을 요구해 140KB 여유 RAM에서 위험하다. 대신 위 3가지(면·테두리·배지 반전)로 "눌림"을 충분히 알린다(배지 반전이 가장 눈에 띈다 — 작은 면이라 번인·눈부심 문제 없음).
- 화면 전체를 밝히는 피드백은 하지 않는다. 가장 밝은 면은 44×44 배지 하나.
- 150ms 이전에는 막대를 보이지 않는다 — 탭에서 막대가 깜빡이는 것을 막는다.
- 대안 타일에 손이 닿은 채 450ms를 넘기지 못하고 뗄 때(150~450ms)는 막대가 사라지며 탭 처리.

### 5.3 길게 누르기 단서

1. **상시**: 대안이 있는 타일 오른쪽 아래 고리 ○ (153,100, 14×14, `--wc-text-3`). 없는 타일(카카오톡)엔 없다.
2. **처음 안내**: 부팅 후 실행 모드에 처음 3번 들어올 때, 쪽 탭 띠 대신 `탭 실행 · 길게 보조` 캡션(20px `--wc-text-3`, x 0~410 가운데, y 466)을 3초 보여 준 뒤 탭 `앱 | 업무`로 되돌린다. 영구 안내 문구는 두지 않는다(화면 아래가 좁다).
3. **진행**: 5.2의 막대와 힌트 `Win+R` 교체.
4. 한계: 대안(Win+R)이 한글 입력 상태에서 실패할 수 있다(launcher.md 2.2). 시계에서 알 수 없으므로 **화면에서 해결하려 하지 않는다**. 설치 안내에 "한/영 영문 상태에서 쓰세요" 한 줄.

## 9. 글꼴·플래시 비용 (이 화면이 요구하는 한글)

**이 화면에서 쓰는 한글**: 앱 라벨(카카오톡·크롬·파워포인트·엑셀·한글) 14자, 배지 글자(웹·엑·한 등) 일부 중복 포함 +2, 2쪽 라벨(캡처·화면 잠금·바탕화면·화면전환·음소거·업무포털) 약 16자, 쪽 탭(앱·업무) 3자, 토스트·이유 문구(주소 미설정 입력 설정 사이트 없어요 필요 Mac 등) 약 22자, 처음 안내(탭 실행 길게 보조) 7자 → **고유 글리프 약 60자 + ASCII**.

| 글꼴 | 쓰임 | 고유 글리프 | 글리프당 압축 크기(추정) | 합계 |
| --- | --- | --- | --- | --- |
| 한글 26px 굵게(body) | 라벨·배지 글자 | 약 45 | 4bpp 약 280B | 약 12.6KB |
| 한글 20px(caption) | 힌트·탭·토스트·이유 | 약 55 | 4bpp 약 180B | 약 9.9KB |
| ASCII 20px / 26px | `Win+Shift+S` 등 | 95 | 약 90B / 150B | 약 8.5 + 14KB |
| 새 아이콘 A8 28×28 × 5 + `i-lock` | 2쪽 배지 | 6 | 784B | 약 4.7KB |

- 이 화면만으로 **약 50KB 안팎**(대부분 ASCII 두 벌이 크다 — 이미 있는 Montserrat 20을 쓰면 ASCII 20px는 0, 26px Montserrat Bold가 새로 필요).
- 전체 KS X 1001 2,350자를 넣을 때(다른 화면 포함 안전책): 26px 4bpp ≈ 650KB, 20px ≈ 420KB, 합 약 1.1MB. 16MB 플래시 안에서는 충분하지만, 글자가 정해지면 **서브셋(수십~수백 자)이 4~10배 작다**. 권장: 모든 화면의 문구를 모아 서브셋 한 벌로 만든다(한 글자 추가 비용 ≈ 0.2~0.3KB).
- 2bpp로 만들면 약 절반. AMOLED 순검정 위 밝은 글자라 2bpp(4단계)도 읽히지만 26px 한글 획이 거칠어지므로 **4bpp 권장**.
- 글꼴 객체 램 비용: LVGL은 폰트를 플래시에서 직접 읽으므로 램은 거의 안 쓴다(캐시 없음).

## 10. LVGL 9.5 구현 메모

### 10.1 객체 수와 스타일

- 타일 6개 × (타일, 색 띠, 배지, 배지 글자, 배지 아이콘(lv_image), 힌트, 라벨, 고리, 막대) = **54개** + 쪽 탭(라벨 2, 밑줄 1, 안내 라벨 1) 4개 ≈ 58개. `lv_obj` 하나 약 150B + 라벨 문자열 → **약 10~12KB**. 현 구현(타일 6 + 라벨 12 + 점 2)보다 약 8KB 늘어난다. 140KB 여유에서 허용.
- 타일 객체는 **한 번 만들고 쪽 전환 때 속성만 교체**한다(재생성 금지: 단편화).
- 공용 `lv_style_t`: `st_tile`(면 #141414, 반경 20, 테두리 1px #333, 패딩 0), `st_tile_pressed`(면 앱 dim, 테두리 2px), `st_tile_dis`(면 #000), `st_badge_sq`(반경 14), `st_badge_circle`(반경 22), `st_hint`, `st_label` + 앱색 6벌 `st_app[i]`(`bg_color` = dim, `text_color` = 앱색, `border_color` = 앱색). 눌림은 `lv_obj_add_state(tile, LV_STATE_PRESSED)` + 스타일에 `LV_STATE_PRESSED` 셀렉터를 걸어 코드 분기를 줄인다(상태가 코어에서 오면 지금처럼 `setBg/setBorder` 직접 호출도 가능).
- 색 띠·막대·고리는 `lv_obj_t` 단색 박스(그라데이션·그림자·outline 사용 안 함). 막대 성장은 `lv_anim`으로 `lv_obj_set_width`를 133까지 300ms(150~450ms 구간) 선형. 손 떼면 `lv_anim_delete` 후 숨김.
- 길게 눌림 타이머: `lv_timer`(450ms 단발). 코어 입력 처리와 별개로 두지 말고 **코어의 hold 판정(core)**이 `HitKind::LaunchTile` + 길게 이벤트를 주도록 `layout.ts`/C++ 동일 테이블에 `hold: 450`을 둔다(테스트 벡터 재현).

### 10.2 렌더 비용

| 항목 | 비용 평가 |
| --- | --- |
| 단색 둥근 사각(타일·배지) | 낮음. 반경 있는 fill은 AA 마스크가 모서리에만 걸림 |
| 2px 테두리 | 낮음(`border_width`). outline·shadow 금지 |
| A8 아이콘 recolor | 중간 이하. 28×28이라 작다 |
| 글자 | 라벨 한 타일 1회. 40줄 버퍼 중 타일 한 행(124px)이 4번 그려진다 |
| 눌림 변경 | 타일 한 개 영역만 invalidate — 183×124 |
| scale transform | **금지**(5.2) |
| 쪽 전환 | 6타일 전부 invalidate(전체 본문 영역) — 1회, 애니메이션 없음 |
| 막대 성장 | 4px × 133px 영역만 invalidate — 프레임당 거의 0 |

- 160MHz 싱글코어에서 6타일 전체 갱신은 40줄 버퍼 기준 약 12~13번 flush. 쪽 전환 직후 한 번이라 문제 없다. 막대 성장(300ms) 동안 다른 갱신이 없도록 입력 중 시계·상태줄 초 갱신은 건드리지 않는다.
- `lv_image` A8 + `image_recolor`는 시스템 문서(4.1) 방식과 같다. 6개 아이콘은 `LV_COLOR_FORMAT_A8` C 배열로 flash(`const`)에 둔다.

### 10.3 웹 시뮬레이터 (sim/)

- `LaunchView`(screens.ts)가 만드는 `watch-tile` 안에 `watch-tile__band`, `watch-tile__badge`(+`--sq`/`--circle`), `watch-tile__ring`, `watch-tile__bar` 요소를 추가하고, `.is-press`, `.is-hold`(막대 진행), `.is-dis`, `.is-off`를 위 7장 표대로 CSS 변수 `--app`, `--app-dim`을 타일에 인라인으로 지정해 그린다. 색은 `data-app="claude|kakao|…"` 속성으로 CSS에서 가져온다.
- CSS transition은 `background-color 80ms`, `border-color 80ms`. **transform: scale 은 시뮬에서도 쓰지 않는다**(실기와 다르게 보이면 안 된다).
- 힌트 폭 자동 숨김(현재 `scrollWidth > 151`)은 107로 바꾸고 `letter-spacing:-1px`를 먼저 적용한 뒤 판단한다.
- 길게 누르기: pointerdown 시 450ms `setTimeout`, 막대는 CSS `transition: width 300ms linear`를 150ms 지연 후 시작. pointermove 24px 초과 시 취소.
- 쪽 탭: 현재 `.watch-launch__pages` 점 DOM을 `앱`/`업무` 두 라벨 + 밑줄 요소로 교체. 클릭 영역은 반으로 나눈다(`launchDots` 히트 타깃에 `side: 0|1` 추가).

## 11. 확인할 것 (실기 월요일)

1. 20px 힌트 `Win+Shift+S`가 107px 칸에 `letter_space -1`로 들어가는지(안 들어가면 `Win+⇧+S` 대신 숨김).
