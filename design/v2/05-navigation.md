# v2-05 모드 전환 체계 · 공통 상태줄 · 당기기 제스처

2026-10-17 · 디자이너 5번 · 범위: 모드 순서·표시, 가로 스와이프 피드백, 모드 색 체계, 상단 상태줄(둥근 모서리 안전 영역), 위에서 당기기 일관성.
전제: 410×502, LVGL 9.5, 싱글코어 160MHz, PSRAM 없음, 40줄 부분 버퍼. 음성 기능 없음. 좌표는 왼쪽 위 (0,0) 기준 px.

## 0. 결정 10개

1. 모드는 **4개 고리**: 시계 → 발표 → 실행 → 회의 → (시계). 왼쪽으로 쓸면 다음, 오른쪽으로 쓸면 이전, 끝에서 순환.
2. 모드 표시는 **상태줄 아래 '레일'**(4칸, 칸 78×3, 간격 6, x 40~370, y 49) + 모드 이름. 화면 중앙 큰 제목(옛 600ms 토스트)은 없앤다. 본문 아래쪽 점 띠(실행 쪽 점과 충돌)도 쓰지 않는다.
3. 스와이프 중에는 **본문을 움직이지 않는다.** 이웃 칸이 dim → 모드색으로 바뀌는 2단계 신호만 준다. 손을 떼면 **4프레임 계단 슬라이드 200ms**(본문 y 56~502만, 상태줄 고정). 프레임이 느리면 즉시 전환으로 자동 후퇴.
4. 시계 모드 색을 흰색(#F2F2F2)에서 **중립 회색 #B8B8B8**로 낮춘다(번인·눈부심). 발표 주황 / 실행 파랑 / 회의 초록은 그대로.
5. 상태줄 공통 레이아웃 확정(3절). 글자·아이콘은 x 40~370, y 12~42 안에만 둔다(곡률 64px 계산 근거 포함). 시계 모드에서는 시각을 숨긴다(큰 시각과 중복).
6. **위에서 당기기**는 모드와 무관하게 하나: 시작 y < 72, 아래로 ≥ 48px → 시트. 발표 시트(344)와 그 밖 모드 시트(136) 두 변형. 닫기: 위로 쓸기 / 바깥 탭 / 3초(발표)·5초.
7. 가로 스와이프 판정: |dx| ≥ 80, |dy| < 60, |dx| > 1.5|dy|, 800ms 이내. **쇼 진행 중에는 |dx| ≥ 140**. 시트·설정이 열려 있으면 모드 스와이프 금지.
8. **터치 동작은 손을 뗄 때(탭: 이동 < 12px, ≤ 350ms) 발동**한다. 누른 순간 발동하면 스와이프 시작이 Win+N·이전/다음으로 새어 나간다. 누르는 즉시 시각 눌림(80ms)은 그대로.
9. 시계로 자동 복귀: 발표 쇼가 돌고 있지 않을 때 무입력 60초 → 시계. 쇼 진행 중에는 다른 모드의 레일에서 발표 칸이 주황 dim(#66370C)으로 남는다.
10. 한글 글꼴 비용: 이 문서가 필요로 하는 글자는 8자(시계 발표 실행 회의), 22px 1벌 ≈ 1.4KB. 추가 RAM ≈ 2KB.

## 1. 모드 고리와 순서

| 순서(레일 칸) | 모드 id | 한글 이름 | 비고 |
| --- | --- | --- | --- |
| 0 | clock | 시계 | 부팅·깨움 기본 |
| 1 | present | 발표 | |
| 2 | launch | 실행 | |
| 3 | meeting | 회의 | |

- 펌웨어 `ModeId` 열거 순서(Present, Launch, Meeting, Clock)와 화면 순서가 다르다. `constexpr ModeId kRailOrder[4] = {Clock, Present, Launch, Meeting}` 표를 하나 두고 스와이프·레일은 이 표의 인덱스만 쓴다. 시뮬레이터도 같은 표.
- 방향 규칙: **손가락이 왼쪽으로 = 레일에서 오른쪽 칸(다음)**. 레일 칸 순서와 손가락 방향이 같아 몸으로 익힌다. 끝에서는 순환하며(회의 → 시계) 슬라이드 방향은 손가락 방향 그대로다(회의에서 왼쪽으로 쓸면 시계가 오른쪽에서 들어온다).
- 시계는 고리의 '집'이다. 회의에서 시계로 가려면 왼쪽 한 번(순환), 발표에서 시계는 오른쪽 한 번. 어느 모드든 최대 2번.
- 깨움: 설정 "손목 들면 시계"가 켜져 있으면 깨울 때 시계, 꺼져 있으면 마지막 모드.
- 자동 복귀: 실행·회의에서 무입력 60초 → 시계(슬라이드 없이 즉시). 발표는 쇼 진행 중이면 복귀하지 않는다(경과 시간이 도는 중). 쇼 시작 전/종료 후 발표 모드는 60초 뒤 복귀.
- 연결 대기·끊김과의 관계: **시계 모드는 BLE 없이도 쓸 수 있어야** 한다(시계니까). 연결 대기 화면(한 번도 연결 안 됨)은 발표·실행·회의 본문만 대체하고, 시계 칸으로 스와이프는 허용한다. (대기 화면 담당과 맞출 것)

## 2. 모드 색 체계

기존 3색 표(system.md 2.2)는 유지하고 시계를 중립색으로 바꾼다. 추가·변경 토큰:

| 토큰 | 값 | 쓰임 |
| --- | --- | --- |
| `--wc-mode-clock` | `#B8B8B8` | 시계 모드 이름·레일 활성 칸. 옛 #F2F2F2 보다 어둡다(검정 대비 약 11:1) |
| `--wc-mode-clock-strong` | `#F2F2F2` | 시계 눌림(설정 진입 등) |
| `--wc-mode-clock-dim` | `#1A1A1A` | 시계 모드의 dim 면 |
| `--wc-mode-clock-dim-border` | `#333333` | 시계 모드의 dim 테두리 |
| `--wc-rail-off` | `#3A3A3A` | 레일 비활성 칸(검정 대비 약 1.8:1 — 위치 표시용이라 낮아도 됨. 칸 모양과 활성 칸 색이 주 신호) |

- `--wc-accent*` 별칭 규칙은 그대로. `data-mode="clock|present|launch|meeting"` 4값. (CSS의 옛 `coding` 이름은 `launch`와 같은 파랑 별칭으로 남긴다.)
- 주황-초록 색각 혼동 대책: **색만으로 구분하지 않는다.** 활성 칸의 위치(0~3번째)와 이름 글자가 항상 같이 있다. 레일 칸 위치가 모드마다 고정이라 색을 못 봐도 "왼쪽에서 두 번째 = 발표"로 안다.
- 상태색은 모드색과 섞지 않는다: 끊김 빨강, 잠금 보라, 경고 노랑은 상태줄 아이콘에만(넓은 면 금지).
- 끊김일 때: 모드 이름 `--wc-text-3`, 레일 활성 칸 `--wc-text-3`(모드색 소등).

## 3. 상태줄 공통 레이아웃 (y 0~56, 모든 모드, 시트 아래층)

### 3.1 안전 영역 계산

패널 모서리 곡률을 반지름 64px로 근사하면, 위에서 y만큼 내려온 줄에서 왼쪽 바깥 비는 폭은 `64 − √(64² − (64−y)²)`.

| y | 비는 폭(px) |
| --- | --- |
| 0 | 64 |
| 10 | 약 30 |
| 14 | 약 24 |
| 28 | 약 11 |
| 49 | 약 2 |

글자(y 12~42)의 위쪽 모서리가 가장 불리하다(y 12에서 약 27). **좌우 40px를 비우면 12px 이상 여유**가 있다. 실제 패널 곡률은 시계에서 확인 후 `SAFE_X`(40) 한 값만 고친다. 모드 이름 칩(전환 직후 반전 표시)만 예외로 x 32부터.

### 3.2 좌표표

```
x:   0       40      104  116     186   218  252  288   318     370   410
y 0   (둥근 모서리 여유)
y12      [시계]   [17:34]               [잠] [BLE] [배터리][82%]
y42
y49      ▬▬▬▬ ▬▬▬▬ ▬▬▬▬ ▬▬▬▬   <- 레일 4칸 (x 40~370, 칸 78x3, 간격 6)
y56  -------- 상태줄 끝 (본문 시작 y 64) --------
```

| 요소 | x, y, w, h | 글꼴·색 | 비고 |
| --- | --- | --- | --- |
| 모드 이름 칩(평소 투명) | 32, 10, 72, 32 | 면 없음 | 모드 전환 직후 600ms만 면 `--wc-accent`, 반경 pill |
| 모드 이름 | 36, 12, 64, 28 | 한글 22px, `--wc-accent`, 가운데 정렬 | 칩 위에서는 `--wc-text-on-accent` |
| 시각 | 116, 12, 70, 28 | Montserrat 20, `--wc-text-1`, 왼쪽 정렬, `HH:MM` | **시계 모드에서는 숨김**. `--:--`(미설정)이면 `--wc-text-3` |
| 잠금 | 218, 12, 28, 28 | 아이콘 A8 28px, `--wc-locked` | 잠금일 때만 |
| BLE | 252, 12, 28, 28 | A8 28px, 연결 `--wc-text-2` / 끊김 `--wc-disconnected` 점멸 | 점멸 500/500ms |
| 배터리 아이콘 | 288, 12, 28, 28 | A8 28px + 잔량 막대 | 색은 system.md 5.2 |
| 배터리 % | 318, 12, 52, 28 | Montserrat 20, 오른쪽 정렬(오른쪽 끝 x 370) | `100%` 약 50px. 충전 중 `82%+` |
| 레일 4칸 | x = 40 + i×84, y 49, 78×3, 반경 2 | 활성 `--wc-accent`, 그 외 `--wc-rail-off` | i = 0..3 (시계, 발표, 실행, 회의) |

- 옛 구조의 모드 점(40,23, 지름 10)과, 펌웨어에서 발표 모드에만 켜던 본문 아래 점 3개는 모두 **레일로 대체**한다. 시뮬레이터와 펌웨어가 같은 모습이 된다.
- 상태줄은 터치 대상이 아니다(탭해도 아무 일 없음). 당기기 시작 영역일 뿐이다(6절). 높이 56은 최소 터치 88px보다 작지만 눌러 쓰는 요소가 아니라 예외.
- 오른쪽 묶음은 잠금이 없어도 BLE·배터리 위치가 변하지 않게 **고정 좌표**. 잠금 칸은 비워 둔다.

### 3.4 모드 이름 칩 (전환 확인)

모드가 바뀌면 이름 칩이 `--wc-accent` 면 + 검정 글자로 **600ms** 반전되었다가 원래(투명 면 + 모드색 글자)로 돌아간다. 중앙 큰 제목을 대체한다. 이유: 중앙 제목은 본문 위에 새 글자 면을 얹어 40줄 버퍼로 여러 조각을 다시 그린다. 칩은 72×32 영역만 두 번(전환 때, 600ms 뒤) 그린다.

### 3.5 번인 방지 (시계 모드)

상태줄 컨테이너(`sbRoot`)를 통째로 움직인다. 시계 담당(이동 규칙)과 같은 `wc_shift(dx,dy)` 값을 받는다. 권장: 90초마다 {(0,0), (2,1), (−2,2), (1,−1)} 순환. 레일은 y 49+2=51 로 내려가도 상태줄(56) 안. 다른 모드는 이동하지 않는다(터치 좌표가 어긋나면 안 됨). 상태줄의 점등 면적은 전체 화면의 1% 미만(글자 4종 + 레일 1칸).

## 4. 가로 스와이프 — 판정과 피드백

### 4.1 판정 (펌웨어·시뮬레이터 동일 함수 1개)

| 항목 | 값 |
| --- | --- |
| 시작 | 화면 어디서든(상태줄 포함). 모드 스와이프가 가능한 화면은 4개 모드 본문뿐 |
| 가로 스와이프 성립 | 이동 \|dx\| ≥ **80**, \|dy\| < **60**, \|dx\| > 1.5×\|dy\|, 누름~뗌 ≤ **800ms** |
| 쇼 진행 중 발표 모드 | \|dx\| ≥ **140**, \|dy\| < 50 (강한 쓸기만) |
| 탭 | 이동 < **12px** 이고 ≤ **350ms** |
| 길게 누름 | 이동 < 12px 로 600ms (발표 중앙 암전, 실행 길게 = Win+R 등). 12px 넘게 움직이면 취소 |
| 허용 안 함 | 시트 열림, 설정 화면, 끊김 배너 흔들림 중(400ms)에는 모드 스와이프 무시 |
| LVGL 내장 `LV_EVENT_GESTURE` | 임계 50px·속도 의존이라 쓰지 않는다. 루트 화면에서 `LV_EVENT_PRESSED/PRESSING/RELEASED` 로 직접 판정(본문 위젯 이벤트는 `LV_OBJ_FLAG_EVENT_BUBBLE`) |

### 4.2 스와이프 중(손가락 닿은 채) — 본문은 안 움직인다

본문을 손가락에 붙여 따라 움직이려면 터치 샘플마다 본문 전체(410×446)를 다시 그려야 해서 실효 10프레임 안팎으로 끊긴다. 대신 **레일만 바꾼다**(다시 그릴 면적 약 330×3).

| 단계 | 조건 | 레일 |
| --- | --- | --- |
| 대기 | 이동 < 16px | 변화 없음 |
| 조짐 | \|dx\| 16~(임계−1), 가로 우세 | 가려는 방향의 이웃 칸이 **그 모드의 dim-border 색**(발표 #66370C, 실행 #183866, 회의 #135331, 시계 #333333) |
| 확정 신호 | \|dx\| ≥ 임계(80/140) | 이웃 칸이 **그 모드 기본색**으로 꽉 참. 지금 떼면 전환된다는 뜻 |
| 취소 | 임계 아래로 되돌림 | 조짐 색으로 복귀 / 16 아래면 원래 색 |

효과: 손가락이 가려는 모드가 **색으로 미리 보인다**(회의 쪽이면 초록 칸이 켜짐). 비용은 `lv_obj_set_style_bg_color` 호출(변화 있을 때만).

### 4.3 손 뗀 뒤 — 4프레임 계단 슬라이드

- 대상: 본문 루트 두 개(나가는 것, 들어오는 것). 상태줄(y 0~56)은 고정. 레일·이름·시각·칩은 **전환 시작 시점에 바로** 새 모드 상태로 바꾼다.
- 동작: 들어오는 루트를 반대쪽 바깥(x = ±410)에 놓고 `HIDDEN` 해제 → `lv_anim` 200ms, **경로 함수를 직접 만든다**:
  `p' = {0.55, 0.85, 0.97, 1.0}[min(3, floor(p*4))]` (4프레임, 앞이 빠르고 뒤가 느린 계단식 ease-out).
  나가는 루트 x = −dir×410×p', 들어오는 루트 x = dir×410×(1−p'). 끝나면 나가는 루트 `HIDDEN`.
- 그리는 양: 프레임당 410×446 ≈ 366KB(RGB565), 40줄 조각 약 11개. 글자·타일은 면 채우기 위주라 CPU 비용은 낮고 병목은 패널 SPI 전송이다. 프레임당 약 25~40ms로 **추정(실측 필요)**. 총 약 100~160ms로 200ms 안에 들어온다.
- **자동 후퇴**: 직전 전환의 첫 프레임 렌더 시간이 60ms 를 넘으면 슬라이드 대신 즉시 컷. 상수 `SLIDE_BUDGET_MS = 60` 하나로 조정. 설정 토글은 두지 않는다.
- 터치: 슬라이드 중에도 막지 않는다. 나가는 루트는 `LV_OBJ_FLAG_CLICKABLE` 해제, 들어오는 루트가 즉시 받는다.
- 쓰는 속성은 오브젝트 `x`와 색 교체뿐. 그림자·투명도 합성·그라데이션 없음.
- 시뮬레이터: 같은 4단계 값 배열을 `requestAnimationFrame`에서 쓴다. `prefers-reduced-motion` 이면 컷.
- 폐기: 280ms 부드러운 슬라이드와 600ms 중앙 제목. `--wc-motion-mode` 는 200ms 로 바꾸고 단계값 토큰(`0.55, 0.85, 0.97, 1`)을 주석으로 추가.

### 4.4 가로 스와이프가 겹치는 곳

| 화면 | 가로 스와이프 |
| --- | --- |
| 시계·발표·실행·회의 본문 | 모드 전환 |
| 실행 모드 쪽 넘김 | **세로** 스와이프(위/아래)로만 쪽 이동. 가로는 모드. 쪽 점(y 462~502) 탭은 쪽 이동. 두 제스처가 직교해 충돌 없음 |
| 쇼 시작/종료 시트·설정 화면 | 모드 전환 금지. 설정에서는 오른쪽으로 쓸기 = 뒤로(설정 문서) |
| 연결 대기 화면 | 시계로만 이동 허용(1절) |

## 5. 탭이 스와이프로 새지 않게 (동작 발동 시점)

system.md 5절은 "누르는 순간 키 전송"이라고 적었다. 스와이프가 타일·좌우 영역에서 시작할 수 있으므로 **그대로 두면 모드를 바꾸려다 Win+1 이나 '이전' 이 먼저 나간다.** 정리:

| 구분 | 누를 때(PRESSED) | 뗄 때(RELEASED) |
| --- | --- | --- |
| 시각 눌림(dim 면, 2px 테두리) | 80ms 안에 즉시 | 스와이프로 판명되면 160ms 에 원복 |
| HID 키 전송 | **보내지 않음** | 탭 조건(< 12px, ≤ 350ms)이면 발동, 이어서 400ms 플래시 |
| 길게 누름 동작(암전·Win+R) | 600ms 시점에 발동(이동 12px 넘기면 취소) | — |

- 손해: 터치→키 지연이 손가락 접촉 시간(보통 80~120ms)만큼 늘어난다. 발표 넘기기에서 체감 거의 없음.
- system.md 5절 및 발표 문서와 **충돌**한다. 합의 전까지는 이 표를 권장안으로 제시.

## 6. 위에서 당기기 — 모든 모드 같은 동작

| 항목 | 값 |
| --- | --- |
| 시작 영역 | 누른 점 y < **72** (상태줄 56 + 여유 16), x 전체 |
| 성립 | 아래로 dy ≥ **48**, \|dx\| < 40, ≤ 600ms |
| 본문 세로 스와이프와의 구분 | 누른 점 y ≥ 72 의 세로 스와이프는 시트를 열지 않는다(실행 쪽 넘김 전용) |
| 중간 피드백 | 손가락을 따라 내려오지 않음. 레일 활성 칸이 `--wc-text-1` 로 잠깐 밝아져 "인식 중" 표시 |
| 열기 | 시트가 위(y = −H)에서 내려오는 **3프레임 계단** 200ms: {0.6, 0.9, 1.0} |
| 시트 면 | `--wc-surface-2`, 아래 모서리 반경 28, 위는 직각(화면 밖), 아래 가장자리 1px `--wc-border` |
| 시트 아래 본문 | `--wc-scrim` 덮개는 **쓰지 않는다**(알파 합성 비용). 시트가 y 0~H 만 덮고 그 아래는 그대로 보임 |
| 닫기 | ① 시트 위에서 위로 ≥ 48 쓸기 ② 시트 바깥(y ≥ H) 탭 ③ 무입력 3초(발표 시트) / 5초(그 외) ④ 측면 버튼 짧게 |
| 닫는 동작 | 열기의 역순 3프레임 200ms |
| 금지 | 시트가 열린 동안 가로 모드 스와이프 |
| 끊김 중 | 열 수 있다(설정은 시계 안 값). 쇼 시작/종료 버튼만 비활성(`--wc-text-disabled`) |

### 6.1 시트 변형

| 변형 | 모드 | 높이 H | 내용 (시트 좌표) |
| --- | --- | --- | --- |

- 시트에 모드 이동 칩을 넣는 안은 채택하지 않았다: 레일 순환(최대 2번 스와이프)으로 충분하고, 시트가 커질수록 발표 중 오조작 위험이 는다.
- 시트 제목(heading 32px)은 없앤다. 버튼 라벨이 곧 설명이고 한글 글자 수도 줄어든다.
- 시트는 상태줄과 레일을 가린다. 열린 동안 시각이 필요한지는 시트 담당이 결정.

## 7. LVGL 구현 메모

### 7.1 오브젝트 (상태줄)

| 이름 | 위젯 | 스타일 |
| --- | --- | --- |
| `sbRoot` | `lv_obj` 410×56 @ (0,0) | 배경 투명·테두리 0·패딩 0, `SCROLLABLE` 해제, 최상위 z. 번인 이동은 이 오브젝트의 x,y |
| `sbChip` | `lv_obj` 72×32 @ (32,10) | `bg_opa` 투명 ↔ `COVER`, 반경 `LV_RADIUS_CIRCLE`. 600ms 뒤 `lv_timer` 1회로 투명 |
| `sbName` | `lv_label` 64×28 | 한글 22px, 색 교체만 |
| `sbTime` | `lv_label` 70×28 | Montserrat 20. 분이 바뀔 때만 `lv_label_set_text` |
| `sbLock`, `sbBle`, `sbBatt` | `lv_image` 28×28, A8 | `image_recolor` + `recolor_opa COVER`, 가시 토글 |
| `sbPct` | `lv_label` 52×28 | 오른쪽 정렬 |
| `rail[4]` | `lv_obj` 78×3 | 반경 2, 테두리·그림자·패딩 없음, `bg_color`만 교체 |

- 위젯 10개는 오브젝트별 로컬 스타일 대신 **공용 `lv_style_t` 3개**(rail, label22, icon)를 `lv_obj_add_style` 해 RAM 절약. 위젯 1개 ≈ 150~200B로 어림해 약 2KB, 애니메이션 구조체 2개 ≈ 160B.
- `render()` 는 직전 값과 비교해 **바뀔 때만** 호출(기존 `setHidden`/`setText` 래퍼 규칙 유지). 레일은 모드가 바뀔 때만 4칸 갱신.
- 본문 루트는 y 56 부터 시작하고 상태줄 아래층에서 클리핑(`OVERFLOW_VISIBLE` 쓰지 않음).

### 7.2 폰트 비용 (한글 서브셋)

| 용도 | 글자 | 크기 | 추정 플래시 |
| --- | --- | --- | --- |
| 모드 이름 | 시 계 발 표 실 행 회 의 (8자) | 22px 4bpp, LVGL 압축 | 글자당 약 170B → **약 1.4KB** |
| 참고: 완성형 2,350자 전부 | — | 22px | 약 400KB (16MB 중 2.5%) |
| 참고: 같은 2,350자 | — | 28px / 40px | 약 650KB / 약 1.3MB |

- 근거: 4bpp 비압축 글리프 ≈ 크기² × 0.5B, 압축 후 70% 안팎으로 어림. 실제 값은 `lv_font_conv` 출력 `.c` 크기로 확인.
- 다른 디자이너 문서의 글자와 합집합으로 서브셋을 만들 것. **한글 글꼴이 아직 없을 때의 임시 표기**는 `CLOCK/PRESENT/LAUNCH/MEETING` 영문(Montserrat 20, 이름 상자 x 36 w 100, 시각 x 150). 최종은 한글.
- 상태줄 숫자·% 는 기존 Montserrat 20(이미 포함) 사용.

### 7.3 전환 코드 골격

```
void switchMode(int dir /* +1 다음, -1 이전 */) {
  newIdx = (idx + dir + 4) % 4;
  setRail(newIdx); setName(newIdx); flashChip(600);
  if (lastFrameMs > SLIDE_BUDGET_MS) { cut(newIdx); return; }
  in = root[newIdx]; out = root[idx];
  lv_obj_set_x(in, dir * 410); lv_obj_remove_flag(in, LV_OBJ_FLAG_HIDDEN);
  lv_obj_remove_flag(out, LV_OBJ_FLAG_CLICKABLE);
  anim(200ms, path = stepEaseOut4, exec = { out.x = -dir*410*p; in.x = dir*410*(1-p) },
       done = { hide(out); in.CLICKABLE });
}
```

## 9. 열린 질문

1. 5절 "뗄 때 발동"을 발표 모드 좌/우 탭에도 적용할지(권장) — 발표 담당과 합의.
2. 시트 B(136)에 공통 빠른 동작을 넣을지 — 지금은 설정 하나뿐.
3. 실제 패널 모서리 곡률 반경 — 실물 확인 후 `SAFE_X` 확정.
4. 슬라이드 프레임 시간 실측 후 `SLIDE_BUDGET_MS`(60)와 단계값 조정. 너무 느리면 슬라이드를 전부 컷으로 바꿔도 레일·칩·판정은 그대로 유효.
