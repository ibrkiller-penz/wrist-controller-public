# 손목 컨트롤러 디자인 시스템

2026-10-16 · 디자인팀 1번(디자인 시스템 리드) · 기준 문서: `../손목컨트롤러_작업지시서.md`

이 문서는 시계 화면(410×502 AMOLED)과 시뮬레이션 사이트가 같은 색·글자·간격·상태 표현을 쓰도록 정한 규칙이다. 값의 원본은 `design/tokens.css`이고, 아이콘 원본은 `design/icons.svg`다. 값을 바꿀 때는 세 파일을 함께 고친다.

- 웹(시뮬레이션·목업): `tokens.css`를 링크하고 CSS 변수를 쓴다.
- 펌웨어(LVGL 9): 아래 표의 hex를 `lv_color_hex(0xRRGGBB)`로 옮긴다. 나중에 `tokens.css` → C 헤더 자동 생성 스크립트를 두면 좋다(keymap.json 헤더 생성과 같은 방식).

## 1. 디자인 원칙

1. **검정이 기본이다.** AMOLED는 검정 픽셀이 꺼져 전기를 쓰지 않는다. 배경은 항상 `#000000`이고, 색 면은 타일·배너처럼 필요한 곳에만 쓴다. 화면 전체를 색으로 칠하는 것은 순간 피드백(400ms 이하)뿐이다.
2. **보지 않고도 누를 수 있게.** 발표 중에는 시계를 거의 보지 않는다. 터치 타깃은 한 변 최소 88px, 발표 모드는 화면을 좌/중앙/우 세 영역으로 크게 나눈다.
3. **모드는 색으로 안다.** 발표=주황, 코딩=파랑, 회의=초록. 상태줄 모드 이름, 활성 테두리, 아이콘 색이 모두 현재 모드색을 따른다.
4. **상태는 색 + 모양 두 가지로 알린다.** 색만으로 상태를 구분하지 않는다(색각 이상, 햇빛 아래). 끊김은 빨강 + 사선 아이콘 + 글자, 잠금은 보라 + 자물쇠 + 글자.
5. **한글이 먼저 읽혀야 한다.** 최소 글자 20px, 라벨은 두 글자~네 글자로 짧게.

### 2.2 모드 색

각 모드는 네 단계를 가진다. dim 은 기본색을 검정 위에 약 18% 로 합성한 **불투명** 값이라 LVGL에서 알파 합성 없이 바로 쓴다.

| 모드 | 기본 (`--wc-mode-*`) | 눌림 (`-strong`) | 면 (`-dim`) | 테두리 (`-dim-border`) | 검정 대비 |
| --- | --- | --- | --- | --- | --- |
| 발표 present | `#FF8A1F` | `#FFA552` | `#2E1906` | `#66370C` | 8.9:1 |
| 코딩 coding | `#3D8BFF` | `#6EA8FF` | `#0B192E` | `#183866` | 6.3:1 |
| 회의 meeting | `#2FD07A` | `#5EDD98` | `#082516` | `#135331` | 10.4:1 |

현재 모드 별칭 `--wc-accent`, `--wc-accent-strong`, `--wc-accent-dim`, `--wc-accent-dim-border`는 화면 루트의 `data-mode="present|coding|meeting"` 값에 따라 자동으로 바뀐다. 컴포넌트는 모드 이름을 직접 쓰지 말고 `--wc-accent*`만 쓴다. 펌웨어도 `mode_color_t current_accent` 하나를 두고 모드 전환 때만 바꾼다.

모드 이름은 `keymap.json`의 모드 id(`present`, `coding`, `meeting`)와 맞춘다. 공유 스키마 담당과 id가 다르면 스키마 쪽을 따르고 이 문서를 고친다.

### 2.4 타이포그래피

글꼴: `Pretendard` → `Apple SD Gothic Neo` → `Malgun Gothic` → `Noto Sans KR` → 시스템 sans. 숫자는 항상 `tabular-nums`(자릿수 고정폭)로 경과 시간이 흔들리지 않게 한다.

펌웨어: LVGL 폰트 변환기로 Pretendard를 필요한 크기만 변환한다. 글리프는 KS X 1001 완성형 2,350자 + 영숫자 + `+ / \` ~ : %` 정도로 제한해 플래시를 아낀다. 디스플레이 112px은 숫자와 `:`만 넣는다.

| 단계 | 토큰 접두 | 크기/줄높이 | 굵기 | 쓰임 |
| --- | --- | --- | --- | --- |
| display | `--wc-type-display-*` | 112 / 112 | 700 | 발표 경과 시간 `12:34` |
| title | `--wc-type-title-*` | 40 / 48 | 700 | 모드 전환 시 모드 이름, 끊김·잠금 전체화면 제목 |
| heading | `--wc-type-heading-*` | 32 / 40 | 700 | 회의 마이크 타일 라벨, 시트 제목 |
| body | `--wc-type-body-*` | 26 / 32 | 600 | 코딩 타일 라벨 (저장, 터미널) |
| label | `--wc-type-label-*` | 22 / 28 | 600 | 상태줄 모드 이름·시각 |
| caption | `--wc-type-caption-*` | 20 / 24 | 500 | 단축키 힌트 `Ctrl+S`, 배터리 % (최소) |

단축키 힌트는 `--wc-font-mono`로 쓴다. 시계에 mono 폰트를 따로 넣기 부담되면 Pretendard로 대체해도 된다.

### 2.6 모션

저전력 MCU라 **위치(transform)와 투명도(opacity)만** 움직인다. 블러·그림자 애니메이션 금지. LVGL에서는 `lv_anim`의 `path_cb`를 `lv_anim_path_ease_out`으로 둔다.

| 토큰 | 값 | 쓰임 |
| --- | --- | --- |
| `--wc-motion-instant` | 0ms | HID 키 전송. 애니메이션을 기다리지 않고 터치 즉시 보낸다 |
| `--wc-motion-press` | 80ms | 눌림 진입 (면색 → strong/surface-2, scale 0.96) |
| `--wc-motion-release` | 160ms | 눌림 해제 복귀 |
| `--wc-motion-fast` | 120ms | 마이크·카메라 아이콘 on/off 교차 페이드 |
| `--wc-motion-base` | 200ms | 시트 열기·닫기, 배너 등장 |
| `--wc-motion-mode` | 280ms | 모드 전환 가로 슬라이드 |
| `--wc-motion-flash` | 400ms | 키 전송 확인 (테두리 1회 점멸) |
| `--wc-motion-toast` | 1600ms | 토스트 유지 |
| `--wc-motion-blink` | 1000ms | 끊김 아이콘 점멸 주기 (500 켜짐 / 500 꺼짐) |
| `--wc-hold-center` | 600ms | 화면 중앙 길게 누름 → 암전(B) |
| `--wc-hold-side` | 2000ms | 측면 버튼 길게 누름 → 잠금 토글 (지시서 고정값) |
| `--wc-gesture-cooldown` | 800ms | 튕김 재인식 금지 (지시서 고정값, `gesture.json`이 원본) |

이징: `--wc-ease-out` = `cubic-bezier(0.2,0,0,1)`, `--wc-ease-in-out` = `cubic-bezier(0.4,0,0.2,1)`. 판정 시간(`hold-*`, `gesture-cooldown`)은 표시용 사본이며 로직의 원본은 `/shared` 설정 파일이다. 값이 다르면 `/shared`가 이긴다.

`prefers-reduced-motion`에서는 시뮬레이터의 시계 화면 전환을 0ms로 한다.

## 3. 화면 골격 (410×502 좌표)

모든 좌표는 왼쪽 위 (0,0) 기준 px.

| 모드 점 | 40, 23, 10, 10 | `--wc-accent` 원 |

좌우 끝 40px은 모서리 곡률(64px) 때문에 비운다. 상태줄 전체가 터치 영역이 아니며, 아래로 스와이프는 상태줄에서 시작해도 된다.

### 3.2 발표 모드

- 세 터치 영역(본문 y 64~486): 왼쪽 0~120(이전), 중앙 120~290(길게 누름=암전), 오른쪽 290~410(다음). 모두 88px 이상.
- 경과 시간: display, 가운데 정렬, 기준선 y ≈ 300. 쇼 시작 전에는 `--wc-text-3`로 `00:00`.
- 좌/우 영역 아래쪽(y 430)에 `‹ 이전` `다음 ›` caption, `--wc-text-3`. 탭하면 해당 영역 전체가 `--wc-accent-dim`으로 400ms 플래시.
- 암전 중: 경과 시간 아래 `암전 중` 칩(`--wc-surface-2`, 반경 sm, `--wc-accent` 글자).
- 에어마우스 중(측면 버튼 누름 유지): 화면 가운데에 지름 160 링(`--wc-accent`, 3px) + "포인터" label. 탭=클릭 안내.
- 음성 듣는 중: 상태줄 아래 y 64, 높이 32 띠에 `i-voice` + "키트, 다음" caption.

앱 선택 칩은 48px 높이지만 칩 위아래 각 20px까지 터치 영역을 늘려 88px을 확보한다. 마이크 타일: 아이콘 96px 가운데, 아래에 heading 라벨 "마이크 켜짐 / 꺼짐".

마이크·카메라 on/off 표시는 **PC 앱의 실제 상태를 알 수 없다**(HID는 단방향). 그래서 시계는 "마지막으로 보낸 토글" 기준으로만 그리고, 타일 길게 누름(600ms)으로 표시만 뒤집는 "상태 맞추기"를 둔다. 화면에 이 한계를 숨기지 않는다.

### 3.5 모드 전환

좌우 스와이프(가로 이동 ≥ 80px, 세로 이동 < 60px). 새 모드 화면이 `--wc-motion-mode`(280ms)로 밀려 들어오고, 동시에 화면 가운데에 모드 이름 title이 `--wc-accent`로 600ms 떠 있다가 사라진다. 순서는 발표 → 코딩 → 회의 → 발표 (순환).

### 3.6 아래로 스와이프 시트 (쇼 시작/종료)

y 0에서 아래로 끌면 높이 240 시트(`--wc-surface-2`, 아래 모서리 반경 lg)가 `--wc-motion-base`로 내려온다. 두 버튼 각 171×120: `i-play` "쇼 시작 F5" / `i-stop` "쇼 종료 Esc". 시트 밖 탭이나 위로 스와이프로 닫힌다. 3초 동안 입력이 없으면 자동으로 닫힌다.

## 4. 아이콘

### 4.1 방침

- 원본: `design/icons.svg` 하나의 `<symbol>` 스프라이트. 아이콘 id는 `i-<이름>`.
- 그리드 24×24, 선 아이콘, 선 두께 2(24 기준), 끝·모서리 둥글게. 채움 아이콘은 쓰지 않는다(AMOLED에서 발광 면적을 줄이고, 모드색을 선 색으로만 입힌다).
- 색은 `currentColor` 상속. 부모 요소 `color`에 `--wc-accent` 또는 상태 토큰을 준다.
- 외부 아이콘 폰트·CDN 금지. 모든 path는 이 프로젝트에서 그린 것이다.
- 크기: 28(상태줄), 48(타일), 96(회의 마이크·전체화면 상태). 96px에서는 선 두께 1.75로 낮춘다(`.wc-icon--lg`).

웹 사용법:

```html
<link rel="stylesheet" href="../tokens.css">
<svg class="wc-icon" aria-hidden="true"><use href="../icons.svg#i-save"/></svg>
```

`file://`로 HTML을 바로 열면 크롬이 외부 SVG `<use>` 참조를 막는다. 목업은 로컬 서버(`npx vite`, `python -m http.server`)로 열거나, 빌드 때 스프라이트를 `<body>` 맨 앞에 인라인으로 넣는다. 시뮬레이션 사이트(Vite)는 `import spriteUrl from '../design/icons.svg?url'` 또는 `?raw` 인라인을 쓴다.

펌웨어 사용법: 스프라이트를 28/48/96px 흰색 PNG로 래스터화 → LVGL 이미지 변환기(`LV_COLOR_FORMAT_A8`, 알파만)로 C 배열 생성 → `lv_obj_set_style_image_recolor(obj, accent, 0)` + `image_recolor_opa = LV_OPA_COVER`로 색을 입힌다. A8이라 한 벌로 모든 색을 쓴다. 래스터화 스크립트는 펌웨어팀 몫이며, 경로는 이 문서에 추가한다.

## 5. 상태 표현 규칙

모든 누를 수 있는 요소(타일, 칩, 시트 버튼)는 다섯 상태를 가진다. 우선순위는 **연결 끊김 > 잠금 > 비활성 > 눌림 > 기본**이며, 높은 상태가 낮은 상태를 덮는다.

| 상태 | 면 | 테두리 | 아이콘·라벨 | 동작 |
| --- | --- | --- | --- | --- |
| 기본 | `--wc-surface-1` | 없음 | 아이콘 `--wc-accent`, 라벨 `--wc-text-1`, 힌트 `--wc-text-3` | — |
| 눌림 | `--wc-accent-dim` | 2px `--wc-accent` | 아이콘 `--wc-accent-strong` | 80ms 진입, scale 0.96. 손을 떼는 순간이 아니라 **누르는 순간** 키 전송. 전송 후 테두리 400ms 플래시 |
| 비활성 | `--wc-bg` | 1px `--wc-border` | 아이콘·라벨 `--wc-text-disabled`, 힌트 숨김 | 터치해도 키를 보내지 않음. 예: keymap에 해당 앱 단축키가 비어 있을 때 |
| 잠금 | 변화 없음 | 변화 없음 | 상태줄 `i-lock` `--wc-locked` 상시 표시 | **터치·버튼은 그대로 동작**하고 제스처·음성만 막는다. 그래서 타일을 흐리게 하지 않는다. 토글 순간 토스트 "제스처·음성 잠김"/"풀림" (`--wc-locked-dim` 면, 1600ms) |
| 연결 끊김 | `--wc-bg` | 1px `--wc-border` | 아이콘 `--wc-text-disabled` | 입력을 보내지도, 쌓지도 않는다(재연결 후 몰아서 보내지 않음). 아래 배너 표시 |

### 5.1 연결 끊김 표시

- 상태줄: `i-ble-off`를 `--wc-disconnected`로, `--wc-motion-blink`(1초 주기) 점멸. 모드 점·이름은 `--wc-text-3`로 낮춘다.
- 본문 아래쪽 배너: x 16, y 414, 378×72, 반경 md, 면 `--wc-disconnected-dim`, 테두리 2px `--wc-disconnected`, 글자 body `--wc-text-1` "연결 끊김 · 다시 연결 중". `--wc-motion-base`로 아래에서 올라온다.
- 끊김 중 입력: 타일·좌우 탭 시 배너가 400ms 흔들림(가로 ±6px 2회) — "보내지 않았다"는 피드백. 진동 모터가 없으므로 화면으로만 알린다.
- 발표 모드에서 끊김: 경과 시간은 계속 흐르되 `--wc-text-3`로 낮춘다.
- 재연결: 배너가 `--wc-success` 점 + "연결됨"으로 바뀐 뒤 1600ms 후 사라진다.
- 시뮬레이터 HID 로그에는 끊김 중 버린 입력을 `--sim-log-dropped` 색으로 "버림" 표시와 함께 남긴다.

### 5.2 배터리

| 잔량 | 막대·숫자 색 | 추가 |
| --- | --- | --- |
| 21% 이상 | `--wc-text-2` | — |
| 11~20% | `--wc-warning` | — |
| 10% 이하 | `--wc-danger` | 한 번만 토스트 "배터리 부족" |
| 충전 중 | `--wc-success` | 막대 위 번개 표시는 생략, 숫자 뒤 `+` |

### 5.3 피드백 원칙

- 모든 키 전송은 눈에 보이는 피드백(눌림 → 400ms 플래시)을 남긴다. 발표 좌우 탭은 해당 영역 전체 플래시.
- 화면 전체를 밝은 색으로 채우는 피드백은 쓰지 않는다(강당에서 손목이 번쩍여 청중 시선을 끈다). dim 면까지만.
- 화면 자동 꺼짐 직전 5초는 전체를 `opacity .5`로 낮춘다.
