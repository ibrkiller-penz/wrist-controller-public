# 시뮬레이션 사이트 레이아웃

2026-10-16 · 디자인팀 4번 · 기준: `../손목컨트롤러_작업지시서.md` 1단계, `system.md`, `tokens.css`, `icons.svg`
목업: `mockups/simulator.html` (로컬 서버 없이 더블클릭으로 열린다. 아이콘 스프라이트를 인라인 사본으로 넣었다.)

시뮬레이션 사이트(`/sim`, Vite + TS)의 화면 골격이다. 시계 화면 **안쪽**(모드별 UI)은 `system.md` 3절과 각 화면 담당 목업이 원본이다. 이 문서는 그 바깥을 다룬다: 툴바, 3단 배치, 시계 기기 모형(베젤·측면 버튼), 가상 PC, HID 로그, 손목 입력 패널, 반응형 배치. 색은 모두 `--sim-*`(사이트)와 `--wc-*`(시계 화면) 토큰만 쓴다.

## 1. 원칙

1. **차분한 데스크톱 툴처럼 보인다.** 사이트 바깥은 회색 계열 `--sim-*` 면, 1px 테두리, 반경 `--sim-radius-lg`(16)의 패널 세 개로 구성한다. 사이트에서 색은 모드 표시와 로그 종류 표시에만 쓴다.
2. **시계 화면은 항상 검정.** `.wc-screen`은 사이트 테마(라이트/다크)와 관계없이 `--wc-*`를 쓴다. 베젤도 테마와 상관없이 어둡다(`--sim-bezel`).
3. **1:1 좌표를 유지한다.** 시계 화면은 410×502 내부 좌표로 그리고, 화면에 맞추는 일은 바깥 상자에 `transform: scale(s)` 하나로만 한다. 터치 좌표는 `(clientX - rect.left) / s`로 되돌린다. 레이아웃 안에서 시계 크기를 직접 바꾸지 않는다.
4. **모든 입력은 로그에 남는다.** 시계가 보낸 것, 끊김으로 버린 것, 무시한 제스처와 음성까지 남긴다. 검증의 근거가 로그다.

### 2.1 브레이크포인트

| 화면 폭 | 그리드 열 | 시계 축척 `s` | 로그 위치·폭 |
| --- | --- | --- | --- |
| 1600 이상 | `auto · minmax(0,1fr) · 360px` | 1.0 (기기 500×542) | 오른쪽 열, 360 |
| 1280–1599 | `auto · minmax(0,1fr) · 320px` | 0.75 (375×407) | 오른쪽 열, 320 |
| 1024–1279 | `auto · minmax(0,1fr)`, 영역 `"watch pc" "watch log"` | 0.75 | PC 아래, 높이 320 |
| 768–1023 | 위와 같음 | 0.6 (300×325) | PC 아래, 높이 320 |
| 767 이하 | 한 열, 영역 `"watch" "pc" "log"` | `min(1, 열폭/500)` (375폭 폰 ≈ 0.69) | 맨 아래, 높이 360 |

- 바깥 여백·패널 간격: `--sim-gap` 16. 폰은 위아래 12, 좌우 16.
- 1600 이상에서 PC 화면 폭은 1600 기준 약 676(높이 423)이다. 그 아래로 PC 폭이 약 500보다 좁아지지 않게 축척을 정했다.
- 축척은 JS 한 함수(`fit()`)로 정하고 `resize`와 `ResizeObserver(body)`에서 다시 계산한다. 폰은 `innerWidth`가 아니라 **시계 열의 실제 폭**으로 계산한다(스크롤바와 확대 때문에 값이 어긋난다).
- 시계 아래 캡션에 `410×502 · 75%`처럼 현재 축척을 보여준다.
- 스크롤: 1280 이상에서는 로그 패널이 `sticky top 72`이고 높이는 `100vh − 88`(최대 960)이다. 1024–1279에서는 시계 열이 sticky다. 폰에서는 sticky를 쓰지 않는다(툴바도 고정 해제).
- 가로 스크롤은 어느 폭에서도 생기면 안 된다. 그래서 1279 이하에서는 툴바 보조 라벨("시뮬레이터", "손목 입력")을 숨기고, 1023 이하에서는 테마 버튼을 설정 화면으로 옮긴다.

## 4. 시계 에뮬레이터

### 4.1 기기 모형 (축척 1 기준 px)

| 요소 | 위치 (x, y, w, h) | 스타일 |
| --- | --- | --- |
| 기기 상자 | 0, 0, 500, 542 | 축척 기준 상자. `transform-origin: 0 0` |
| 베젤 | 0, 0, 450, 542 | 반경 84 (화면 64 + 베젤 20), `--sim-bezel`. 안쪽 2px 링 `--sim-bezel-edge`, 6px 지점에 1px 링 하나 더(금속 단 느낌), `--sim-shadow` |
| 화면 `.wc-screen` | 20, 20, 410, 502 | `tokens.css` 공용 클래스 그대로, 반경 64 |
| BOOT 버튼(위) | 448, 150, 12, 64 | `--sim-side-button`, 1px `--sim-bezel-edge`(왼쪽 없음), 반경 0 6 6 0 |
| PWR 버튼(아래) | 448, 250, 12, 64 | 같음 |
| 버튼 라벨 | 466, 166 / 266, 34 폭 | `BOOT` / `PWR` mono 11/700 `--sim-text-3`, 아래에 단축키 `Space` / `P` 10px |
| 길게 누름 진행 막대 | 462, 150 / 250, 3, 64 | `--wc-locked`, 아래에서 위로 2000ms 선형으로 차오름 |

- 측면 버튼의 실제 히트 영역은 34×88이다(`::before`로 위아래 12, 오른쪽 16 확장). 보이는 크기는 12×64다.
- 눌림: `translateX(-4px)` + 면 `--sim-bezel`, 진입 80ms(`--wc-motion-press`), 복귀 160ms. 실제 버튼이 들어가는 느낌을 준다.
- **버튼 실물 위치(오른쪽 면): 위 = BOOT, 아래 = PWR**(2026-10-18 실물 확인). 펌웨어 핀은 BOOT GPIO9, PWR GPIO18 그대로.

### 4.2 측면 버튼 역할 (제안: 펌웨어팀과 키맵 담당 확인 필요)

| 버튼 | 키보드 | 짧게 (<400ms) | 길게 2000ms | 누른 채 손목 이동 |
| --- | --- | --- | --- | --- |
| BOOT (주 버튼, 위) | Space | 모든 모드: 시계 모드로(이미 시계면 직전 모드로). 키 안 보냄 | 제스처·음성 잠금 토글 | 에어마우스 |
| PWR (아래) | P | 시계 화면 켜기·끄기 | 잠금 토글 (BOOT와 같게) | — |

- 주 버튼을 BOOT로 제안한 이유: GPIO0이라 MCU가 직접 읽어 지연이 짧다. 반면 PWR은 PMU(AXP2101 계열)를 거치고, PMU가 길게 누름을 전원 끄기로 해석할 수 있다. 확인 전까지는 시뮬레이터에서 `keymap.json`의 버튼 매핑을 바꿀 수 있게 둔다.
- 짧게 누른 동작은 **손을 뗄 때** 판정한다. 누른 동안 손목 움직임이 데드존을 넘으면 에어마우스로 바뀌고, 그러면 뗄 때 "다음"을 보내지 않는다. 움직임 없이 2초가 지나면 잠금으로 바뀐다. 이 판정은 모드 상태 기계 담당이 원본이다.
- Space 키는 입력칸·셀렉트에 포커스가 있을 때는 가로채지 않는다. 키 반복(`e.repeat`)도 무시한다.

### 4.3 화면 입력 흉내

| 마우스·터치 동작 | 시계 이벤트 | 판정 기준 (원본은 /shared) |
| --- | --- | --- |
| 클릭 (이동 12px 미만) | 탭 | — |
| 누르고 600ms | 길게 누름 (발표 중앙 = B) | `--wc-hold-center` |
| 가로 드래그 ≥ 80, 세로 < 60 | 모드 전환 스와이프 | system.md 3.5 |

- 시계 화면 커서는 `pointer`이고 `touch-action: none`이다(폰에서 스와이프가 페이지 스크롤로 새지 않게).
- 키보드만 쓰는 사용자를 위해 화면에 포커스가 있을 때 `←`/`→` = 왼쪽·오른쪽 탭, `Enter` = 중앙 탭을 둔다(목업에는 없음, 구현 권장).

### 4.4 손목 움직임 패널 (시계 바로 아래)

폭 = 시계 열 폭(최대 500), 패널 헤더 44 `손목 움직임` + 현재 입력 방식 설명. 본문 패딩 12, 간격 10.

| 입력 방식 | 본문 |
| --- | --- |
| 마우스 드래그 | 높이 160 패드. `--sim-surface-2` 면, 1px 점선 테두리, 가운데 십자선 1px `--sim-border`. 손잡이 점 20(`--sim-mode-coding`, 4px `--sim-surface` 링). 끌면 dx→gy, dy→gx로 각속도를 만든다. 놓으면 점이 가운데로 돌아가고 값은 0이 된다(드리프트 없음 확인용). 아래에 안내 글자 12 `--sim-text-3` |
| 폰 센서 | `폰 기울기 센서 사용 중 · β +12° γ −4°` 와 `센서 권한 요청` 버튼(iOS는 사용자 동작 안에서 `DeviceOrientationEvent.requestPermission()` 필요) |
| 녹화 재생 | 파일명(mono), 재생 `i-play` / 정지 `i-stop` 36 버튼, 위치 슬라이더, `00:41 / 02:00 · 1×`. 파일은 2단계 시리얼 CSV |

공통으로 아래에 `gx gy gz` 세 줄 막대를 둔다(열 28 · 1fr · 64). 막대는 가운데 0 기준 좌우로 차고 `--sim-text-3`이며, 숫자는 mono tabular다.

- 폰에서는 썸네일 열을 숨긴다.
- 에어마우스 중에는 쇼 화면에도 커서를 보인다.

### 5.5 회의 창 (회의 모드)

틀은 상단 4cqw(앱 이름 굵게 · `주간 회의 · 00:18:42` · `참가자 4`) / 2×2 참가자 격자(간격 1cqw) / 하단 컨트롤 7.5cqw다.

- 참가자: 나(손목 컨트롤러), 김지원(말하는 중: 0.3cqw `--sim-mode-meeting` 테두리), 박서준(음소거), 이하늘. 아바타는 원 8cqw에 두 글자를 넣는다. 지어낸 이름이다.
- 하단 버튼 3개(원 4.4cqw + 라벨): 마이크 / 카메라 / 손 들기. 켜짐 = `--sim-mode-meeting` 아이콘 + 2px 외곽선. 꺼짐 = `--sim-log-dropped` + off 아이콘(`i-mic-off`, `i-camera-off`). 키를 받으면 400ms 동안 1.15배로 튀었다 돌아온다.
- 손 들기: 내 타일 오른쪽 위에 `✋ 손 듦` 표시(`--sim-notice-bg`/`-text`).
- 마이크 끔: 내 이름표에 `i-mic-off`.
- 시계에서 앱 칩(Zoom/Teams/Meet)을 바꾸면 상단 앱 이름과 단축키 해석이 바뀐다. 시뮬레이터에서는 PC가 "그 앱이 떠 있다"고 가정한다.

### 5.6 가상 마우스 커서

- 20×20 화살표 SVG. 면 `--sim-text-1`, 1.5px 외곽 `--sim-surface`, 그림자 1px. 위치는 가상 1920×1200 좌표를 화면 %로 바꿔 `left/top`에 넣는다. 이동 보간은 60ms linear(HID 보고 주기 흉내)다.
- 클릭: 지름 28 원 파문, 2px `--sim-mode-coding`, 300ms 동안 0.3→1.4배로 커지며 사라진다.
- 에어마우스가 꺼지면 커서는 마지막 위치에 그대로 둔다. 흐르면 버그다(체크리스트 항목).
- 실제 사용자 마우스 커서는 PC 화면 위에서 기본 커서를 그대로 쓴다(가상 커서와 헷갈리지 않게 가상 커서에는 그림자를 넣는다).

| 요소 | 치수 | 내용 |

| 하단 | 32, 글자 12 | `마우스 이동은 100ms씩 묶음` · `자동 스크롤 ●` |

**행 구성**

- 왼쪽 3px 띠 + 종류 배지(높이 20, 1px 테두리, mono 10/700)는 같은 종류 색이다. **색과 글자(KEY/MOUSE/MEDIA/SYS)를 함께** 쓴다(색만으로 구분하지 않는 원칙).
- 시간: 페이지 시작 기준 `mm:ss.mmm`, mono 12 `--sim-text-3`.
- 내용: mono 13 `--sim-text-1`, 보조 설명은 `--sim-text-3`. 예: `→ Right · 0x4F`, `Ctrl+Shift+P 명령`, `이동 Δx +38 Δy −12 ×18`, `볼륨 − 0x00EA`. 넘치면 말줄임하고 툴팁에 전체를 보인다.
- 출처: 11 `--sim-text-3`. 값은 터치 / 버튼 / 제스처 / 음성 / 에어 / 길게 / 스와이프 / 시트 / 시스템 / 사이트.
- 새 행은 `--sim-surface-2`에서 200ms에 걸쳐 원래 면으로 돌아온다.

| 종류 | 토큰 | 배지 | 예 |
| --- | --- | --- | --- |
| 키보드 | `--sim-log-key` | KEY | `F5 쇼 시작 · 0x3E` |
| 마우스 | `--sim-log-mouse` | MOUSE | `왼쪽 클릭`, `이동 …` |
| 미디어 (consumer) | `--sim-log-media` | MEDIA | `볼륨 − 0x00EA` |
| 시스템 | `--sim-log-system` | SYS | 연결·끊김, 모드 전환, 잠금, 무시된 제스처·음성 |
| 버림 | `--sim-log-dropped` | (원래 종류 유지) | 띠·배지 색만 빨강, 내용 취소선, 뒤에 `버림` 11/700 |

- 마우스 이동은 연속된 이동을 **100ms 창으로 합쳐 한 줄**로 보인다(`×18` = 묶인 보고 수). 클릭·키는 묶지 않는다.
- 자동 스크롤: 맨 아래에 있을 때만 따라간다. 사용자가 위로 올리면 멈추고 하단에 `새 기록 N건 ↓` 버튼을 띄운다.
- 일시정지는 표시만 멈춘다(기록은 계속). 내보내기 JSON은 `/shared/test-vectors/` 형식과 맞춘다(스키마 담당 확인).
- 행이 1000개를 넘으면 오래된 것부터 지운다(가상 스크롤은 필요 없음).

## 9. 접근성

- 영역 이름: 툴바 `role="toolbar"`, 시계 화면 `role="application"`(aria-label에 조작법), 로그 목록 `role="log" aria-live="polite"`.
- 포커스 링은 2px `--sim-focus`, 간격 2px이며 모든 버튼에 적용한다.
- 측면 버튼에는 `aria-label`로 단축키를 적는다("BOOT 버튼(위). 짧게 = 시계 모드 ↔ 직전 모드 … (단축키 Space)").
- 라이트 테마 사이트 모드색은 `--sim-mode-*`(흰 면 대비 4.5:1 이상)를 쓴다. `--wc-mode-*`를 흰 면에 쓰지 않는다.

## 10. 구현 메모

- 아이콘: 사이트도 `design/icons.svg`를 쓴다. Vite에서는 `?raw`로 `<body>` 앞에 인라인하고 `<use href="#i-…">`로 참조한다. 툴바 아이콘 크기는 18, 선 2다.
- 스프라이트에 **없는** 아이콘(손목 입력 방식 3종, 테마 해·달, 외부 링크)은 글자 라벨로 대신했다. 아이콘이 필요하면 디자인팀 1번에게 `i-drag`, `i-phone-tilt`, `i-replay` 추가를 요청한다.
- 목업 맨 아래 점선 상자 "목업 상태"는 상태를 바꿔 보는 개발용 장치이며 실제 사이트에는 넣지 않는다. 단, 같은 기능을 `?debug=1`일 때 보이는 개발자 패널로 두면 검증할 때 편하다.
- 목업 JS의 판정(튕김 = 180ms 안에 60px 이상, 길게 = 600ms 등)은 보여주기용 단순화다. 실제 값은 `/shared/gesture.json`과 상태 기계 구현을 따른다.
